# API 매뉴얼(M2) 대조 — 클라이언트가 임의로 만들어 내는 데이터 출력·검증 항목 (2026-08-28)

> 기준: `docs/API 매뉴얼 최신본/*.pdf`(목차 M2 + 객체/엔드포인트 명세) vs 현재 목업 UI(커밋 `a53002a`).
> 분류: **A 임의 검증(판단)** / **B 임의 생성 데이터(API 스키마에 없는 값)** / **C 클라이언트 상태(API 미저장, 출력에는 영향)** / **D 표시용 파생값(계산·집계, 데이터 아님)**. 결정 필요 항목은 ⚑.

## A. 임의 검증(판단) — API 응답에 없는 클라이언트 판단
| 항목 | 위치 | API 대조 | 조치 |
|---|---|---|---|
| 종속항 선행 근거 경고 "'입력부'가 제N항에 없습니다" | 청구항 단계 종속항 카드 | `dependent-claim` 응답은 `{no, value, depends_on, category, element_ids, explanation, is_modified}` — 검증 결과 없음 | **이번 버전 제외** (`ENABLE_ANTECEDENT_CHECK=false`, 커밋 `a53002a`). 연동 시 `element_ids` 기반으로 재검토 |
| 구성요소 "보완 필요" 배지 + 진행 확인 | 구성요소 단계 | `InventionElement` 필드 중 빈 값 검사(클라이언트) | ⚑ 유지 여부 결정 — 입력 누락 안내이지 판단은 아님 |
| 에디터 청구항 "⚠ 번호 확인"(인용 번호가 자기 번호 이상) | 에디터 청구범위 | API 없음 | ⚑ 유지 여부 결정 (형식 검사) |

## B. 임의 생성 데이터 — API 스키마에 없는 값을 클라이언트가 만들어 출력
| 항목 | 위치 | API 대조 | 조치 |
|---|---|---|---|
| 에디터 섹션 **"요약"** (확정 개요 + `【대표도】 도 N`) | 에디터·미리보기·DOCX/PDF | `InventionSpecification`에 요약(abstract) 필드 없음. 개요는 `InventionContext.summary`(API) | ⚑ 요약서 출력이 필요하면 클라이언트 조립으로 유지, 아니면 제외. `【대표도】`는 API 개념 없음(대표 이미지는 요청 시 최대 3개 전달만) |
| 에디터 섹션 **"부호의 설명"** (`100: 데이터 수집부` 표) | 에디터·미리보기 | `InventionSpecification`에 없음. `InventionElement.symbol`(Optional)에서 조립 | ⚑ 동일 |
| 도면 설명 자동 문장 `도 N은 …를 나타낸 도면이다. (대표도면)` | 청구항 확정 시 중간명세서 | 실 API `/generate/specification/brief-drawing-descriptions`가 생성(목업 대체). **`(대표도면)` 접미**는 API 없음 | 연동 시 API 문장으로 대체, `(대표도면)` 접미 제거 |
| 구성요소 **부호 자동 부여**(100·200…, 하위 110) | 구성요소 단계 | `InventionElement.symbol`은 Optional str — 추출 API 응답 예시에 symbol 없음 → 부호는 사용자/클라이언트가 정함 | 유지(입력 보조). API에 값으로 전달됨 |
| 명칭 후보 **"추천 이유"**(`reason`) | 명칭·요약 단계 카드 | `/v2/generate/context/abstract` 명세 PDF가 폴더에 없어 응답 필드 미확인(목차에만 존재) | ⚑ **확인 필요** — API가 reason을 주지 않으면 제외 |
| 독립항 세트 부제 "등록 가능성과 보호 범위 균형" 등 | 청구항 세트 카드 | `abstraction_level`(BROAD/INTERMEDIATE/NARROW)은 API, 설명 문구는 클라이언트 | 표시 문구이므로 유지 가능(용어 사전에 등재) |
| AI 수정 제안 "✦ 지시를 반영해 표현을 보완했습니다" | 위저드 제안 카드 | modification API들에 `explanation` 있음 — 현재는 mock 문장 | 연동 시 API `explanation`으로 대체 |
| 에디터 제안 `action: REWRITE/REPLACE/INSERT/DELETE` | 에디터 AI 패널 | `SpecificationEditorChatMessage.edit_proposals: SpecificationBodyEditProposal` — 필드 상세가 매뉴얼에 없음(개발노트 기준) | ⚑ 확인 필요 |

## C. 클라이언트 상태 — API 객체에 없는 플래그(저장 안 됨)
| 항목 | 위치 | 비고 |
|---|---|---|
| `Drawing.included / useForSpec / isRepresentative / cadConverted` | 이미지 선별·명세서 도면 | API `Drawing`은 `image + detail`만. 대표 이미지는 API 요청 시 "drawings에 대표도 최대 3개만 제공"으로 쓰임 → 요청 구성 시 이 플래그로 필터링 |
| `InventionDescriptionItem.adopted` | 발명 설명 채택 | API 요청 시 채택 항목만 보내는 필터 용도 |
| 발명 설명 라벨 표시명 "구성(해결수단)/종래 구성" | 발명 설명 | API `label`은 `background/implementation/objective/effect/etc`(문자열) — 표시명만 매핑. **`etc` 라벨은 클라이언트 타입에 없음** → 수신 시 표시 필요 |
| 도면 라벨 `etc` | 이미지/도면 카드 | API `DrawingDetail.label`에 `etc` 있음, 클라이언트 select 옵션에 없음 → 추가 필요 |
| 청구항 단계 내부 상태(세트 생성·선택·종속항 편집) | 청구항 단계 | localStorage 미저장(재진입 시 초기화) — 기존 한계 |

## D. 표시용 파생값(데이터 아님) — 유지
사이드바 진행 배지 · AI 패널 "확정 N/8" 요약 · 세트 라벨 "장치항 + 방법항 · 구성요소 K개"(`element_ids` 집계) · 종속항 "채택 N" · 구성요소 명칭 하이라이트/전역 치환(텍스트 로직) · 청구항 인용 번호 자동 갱신(에디터, `depends_on` 개념과 일치).

## 결정 (2026-08-28 사용자)
1. **요약·부호의 설명 섹션 유지** — 클라이언트 조립(개요는 API `summary`, 부호표는 `elements`).
2. **대표도는 이용자가 지정** — `isRepresentative`는 클라이언트 상태로 유지, 요약의 `【대표도】`와 API 요청의 대표 이미지 필터에 사용.
3. **부호 자동 부여는 이용자 도구** — 유지(값은 API `symbol`로 전달).
4. **추천 이유는 API 응답**(abstract API가 제공) — 유지.
5. **`etc` 라벨** — 발명 설명·도면 모두 수신 대응 추가(표시명 "기타").
6. ⏳ 보완 필요 배지·번호 확인 배지(형식 검사) — 미결(기본 유지).

### 2026-08-31 도면 변환툴 범위 결정 (사용자 확정)
- 이번 범위: 도면 선택 → 영역 확인(크롭·BBox) → **CAD 변환·명시적 완료**까지. `ENABLE_DRAWING_EDIT=false`로 도면 편집(부호 배치, PatentEditor) 단계 제외 — API(M2)에 대응 기능 없음.
- CAD 변환 완료 = 후보 선택 후 「✓ 이 버전으로 CAD 변환 완료」 → stage `done` + 선택본 확정 → 완료 화면(초록 ✓) + 목록 배지 「변환 완료」 + 메인 탭(위저드·에디터) 「CAD 변환 완료」 배지·썸네일 반영.
- API(`/generate/drawing/style-transfer`) 대조: `user_instruction`(변환 지시문 — 크롭 단계 입력 추가·재변환 프롬프트 기존), `num_images` 1~4(후보 3개), `bbox` 서버 크롭 — 모두 API 제공 기능으로 유지. **UI 미노출 파라미터**: `provider`(auto/openai/gemini)·`quality`(low/medium/high) — 연동 시 기본값(auto) 사용 또는 노출 여부 결정 필요.
