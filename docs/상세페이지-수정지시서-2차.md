## 1. 오류 A — 국제공개(WO) 113건

### 현재 화면 (`KR 10-2635013 B1`)

```
문헌번호      10-2635013 B1      공고일     2011-11-24    ← 등록일(2024-02-05)보다 13년 앞선다
국제공개번호   WO 2011/146808     공개일     2022-07-26    ← 번호와 일자의 계열이 어긋난다
```

### 무엇이 틀렸나

| 값 | 필드 | 현재 라벨 | 실제 의미 |
|---|---|---|---|
| `2011-11-24` | `publication_date` | 공고일 ❌ | **국제공개일** — `WO 2011/146808`이 공개된 날 |
| `2022-07-26` | `open_date` | (국제공개번호 옆) 공개일 ❌ | **국내 공개일**(번역문 공개) |

**근거**: WO 계열 **113건 전부** `publication_date < register_date`. 공고는 등록 이후에 나오므로 이 값은 공고일이 될 수 없다. 그중 **112건**은 `open_date > publication_date`(국내공개가 국제공개보다 나중)로, 두 값이 서로 다른 사건임이 확인된다.

### 수정 후 기대

```
문헌번호      10-2635013 B1      공개일      2022-07-26    ← open_date (국내 공개일)
국제공개번호   WO 2011/146808     국제공개일   2011-11-24    ← publication_date · 짝 일치
                                                          (이 문헌에는 공고일 데이터가 없다 → 표시하지 않음)
```

### 확인용 문헌

| 문헌번호 | `publication_date` | `open_date` | 등록일 |
|---|---|---|---|
| `KR 10-2635013 B1` | 2011-11-24 | 2022-07-26 | 2024-02-05 |
| `KR 10-2635400 B1` | 2020-01-23 | 2022-10-25 | 2024-02-05 |
| `KR 10-2635881 B1` | 2019-08-15 | 2020-10-14 | 2024-02-06 |
| `KR 10-2649993 B1` | 2021-04-08 | 2022-06-03 | 2024-03-18 |
| `KR 10-2634993 B1` | 2018-07-05 | 2019-08-27 | 2024-02-05 |

## 2. 오류 B — 공고일이 아닌 값을 「공고일」로 표기 (2건)

### 현재 화면 (`KR 20-0497874 Y1`)

```
문헌번호   20-0497874 Y1        공고일   2023-04-05    ← 등록일(2024-03-18)보다 앞선다
공개번호   20-2023-0000689      공개일   (빈칸)
```

`2023-04-05`는 공고일이 아니라 **공개일**이다. 원본에 `open_date`가 없어(적재 결손) `publication_date` 자리에 공개일이 들어가 있다.

### 수정 후 기대

```
문헌번호   20-0497874 Y1        (공고일 데이터 없음 → 칸 비움)
공개번호   20-2023-0000689      공개일   2023-04-05
```

### 확인용 문헌

`KR 20-0497874 Y1` · `KR 20-0497883 Y1` (둘 다 실용신안, 원본 `open_date` 결손 — 적재 측 F-18과 같은 문헌)

## 3. 수정 방법 — 판정식에 일자 검증 추가

1차 지시서 §3은 **번호 형식만** 보고 짝을 정하게 했다. 여기에 **「그 값이 정말 공고일인가」** 검사를 넣는다.

```ts
// 공고는 등록 이후에 나온다. 이 조건을 통과해야만 '공고일'로 쓸 수 있다.
const isBulletinDate = !!(pubDate && regDate && pubDate >= regDate);

if (/^\d{2}-\d{4}-\d{7}$/.test(pubNo)) {           // ① 공개계 985건 — 현행 유지
  공개번호 = pubNo;
  공개일   = openDate;
  공고일   = isBulletinDate ? pubDate : null;       // ← 2건(오류 B)이 여기서 걸러진다
}
else if (/^WO \d{4}\/\d{6}$/.test(pubNo)) {         // ② 국제공개 113건 — 수정 대상(오류 A)
  국제공개번호 = pubNo;
  국제공개일   = pubDate;                            // ← publication_date 와 짝을 맞춘다
  공개일       = openDate;                           // ← 국내 공개일(문헌번호 행 우측)
  공고일       = isBulletinDate ? pubDate : null;    // → 113건 모두 null
}
else if (/^\d{2}-\d{7}$/.test(pubNo)) {             // ③ 공고계 314건 — 현행 유지
  공고번호 = pubNo;
  공개일   = openDate;
  공고일   = pubDate;
}
else {                                              // ④ 번호 없음 392건 — 현행 유지
  공개 행 숨김;
  공고일 = isBulletinDate ? pubDate : null;
}

// 공통 원칙: isBulletinDate 가 false 인데 pubDate 가 있으면 그 값은 공고일이 아니다.
//           번호 계열에 맞는 라벨(국제공개일 / 공개일)로 쓰거나, 판단이 안 서면 표시하지 않는다.
```

**라벨 위치는 1차와 동일**하다. 행을 새로 만들지 않는다.

| 행 | 좌측(라벨·값) | 우측(라벨·값) |
|---|---|---|
| 0 | `문헌번호` · 번호 | **계열에 따라** `공고일` 또는 `공개일` |
| 2 | `공개번호`/`국제공개번호`/`공고번호` · 번호 | `공개일`/`국제공개일` |

## 7. 원인과 재발 방지

이 2건은 **1차 지시서의 판정식 오류**에서 나왔다. 번호 형식만으로 일자 계열을 정하게 했고, `publication_date`가 항상 공고일이라고 전제했다. 실제 데이터에는 그 전제를 깨는 값이 **115건**(WO 113 + 실용신안 2) 있었다.

재발 방지로 **일자 논리 검증**을 규칙에 넣는다.

```
공고일  ≥ 등록일        (공고는 등록 이후)
공개일  ≤ 등록일        (공개는 등록 이전)
국제공개일 ≤ 국내 공개일 (해당 시)
```

이 조건을 어기는 값이 나오면 **라벨을 붙이지 말고 로그로 남긴다.** 향후 공개 문헌·해외 문헌이 적재되면 같은 유형의 값이 더 나올 수 있다.
