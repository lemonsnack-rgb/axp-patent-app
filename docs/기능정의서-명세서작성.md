## 1. 전체 이용 흐름

이용자(변리사·연구자)는 **직무발명서(A-01) PDF 하나**로 시작한다. AI가 뽑아 준 초안을 단계마다 **확인 → 수정 → 확정(B-03)** 하며 내려가고, 앞 단계의 확정 내용이 다음 단계 생성의 재료가 된다. 8단계가 끝나면 실시예를 포함한 **명세서(A-02)** 가 생성되어 에디터로 넘어가고, 편집 후 DOCX·PDF로 내보낸다. 모든 진행 상태는 자동 저장되어(B-15) 언제든 이어서 할 수 있다.

| 단계 | 이용자가 하는 일 | 시스템(AI)이 하는 일 | 이때 붙는 API |
|---|---|---|---|
| 작업 생성 | 작업 이름·기술분야(선택) 입력 후 「명세서 작성 시작」 | 작업(B-01)을 만들고 ①로 진입 | — (클라이언트 상태) |
| ① 업로드 | 직무발명서 PDF 1개 업로드 | 발명 설명·도면 이미지를 추출 | `POST /v2/extract/idf/description` · `POST /v2/extract/idf/drawing` — 페이지 이미지들을 보내고 설명 항목·도면(BBox 포함)을 받는다 |
| ② 발명 설명 | 항목을 제안/종래로 검토, 쓸 것만 채택·편집 | 원천 정보를 정제해 항목으로 제시, 요청 시 AI 수정(항목/전체) | `/v2/generate/context/description/refined`() · `…/description/item-modification`(항목 AI 수정) · `…/description/modification`(전체 AI 수정) |
| ③ 이미지 선별 | 맥락에 쓸 이미지 선택, 대표 이미지 1개 지정 | — (추출 결과 표시) | — (①의 추출 결과 사용, 선택 플래그는 클라이언트) |
| ④ 명칭·요약 | 명칭 후보 중 선택 또는 직접 입력, 요약 확정 | 명칭·요약·추천 이유 후보 생성 | 명칭·요약 생성 API(매뉴얼 미제공 — 연동 시 확인) |
| ⑤ 구성요소 | 명칭·정의 보완, 순서·계층 조정, 부호 부여 후 확정 | 발명 설명에서 구성요소 후보 추출 | `/v2/generate/context/invention-element`(추출·다시 분석) · `…/item-modification`·`…/modification`(AI 수정) |
| ⑥ 명세서 도면 | 도면 채택(도 N)·대표도면 지정, 필요 시 도면 편집기에서 크롭·CAD 변환 | — | `POST /generate/drawing/style-transfer`(CAD 변환 — §3.12) |
| ⑦ 청구항 | 권리범위 설정 → 독립항 세트 1개 선택 → 종속항 채택·편집 → 확정 | 세트 후보(최대 5개)·종속항 생성 | `/v2/generate/specification/independent-claim/set` · `…/independent-claim/modification` · `…/dependent-claim` · `…/dependent-claim/item-modification`·`…/modification` |

## 2. 화면 지도

```
[새 명세서 작성]  폼(작업 이름·기술분야) + 진행 방식 3단계 안내
      ↓ 명세서 작성 시작
[작성 단계(위저드)]                              [에디터]
 ┌─ 스텝바(8단계) ──────────────┐                ┌─ 툴바(편집 도구) ───────────────┐
 │  본문: 단계 패널   │ AI 어시스턴트 │   ⇄ 이동    │  ←작성 단계로 | 섹션 탭 11종      │
 │  (①~⑧ 세로 나열)  │ (작성 안내)  │                │  본문: 섹션·단락 카드 │ AI 어시스턴트│
 ├─ 하단 바: ←이전 · 주 동작 1개 ─┤                │                      │ (본문 수정)  │
 └──────────────────────────┘                └─ 명령 입력창 ────────────────────┘
      ⑥/에디터 도면 카드 → 새 탭 [도면 편집기]: 도면 목록 | 영역 확인(크롭) → CAD 변환 → 완료
```

## 3. 화면·영역별 상세

각 절의 표 형식: **기능 요소 | 표시 기준 | 이용자 동작 → 결과 | 연결 API | SPC**. AI 수정류의 공통 동작은 §3.13에 한 번만 정의한다.

### 3.1 새 명세서 작성 폼

**여기서 이용자가 하는 일** — 작업 하나를 만들고 시작한다. 두 입력 모두 선택 사항이라 빈 채로도 시작할 수 있다.

| 기능 요소 | 표시 기준 | 이용자 동작 → 결과 | 연결 API | SPC |
|---|---|---|---|---|
| 입력 폼 | `작업 이름 (선택)`(80자)·`기술분야 (선택)`(60자). 이름 아래 보조문 "발명의 명칭을 입력하면 명세서 작성 중 자동 반영됩니다." | 입력(Enter=시작) | — | WIZ-010 |
| 명세서 작성 시작 | primary 버튼, 항상 활성 | 클릭 → 작업 생성(미입력 시 이름 `새 명세서`) → ① 업로드 진입 | — | WIZ-011 |

**동작 원리** — 8단계 패널이 본문에 세로로 쌓인다. 현재 단계만 열려 있고, 확정한 단계는 1줄 요약으로 접힌다. **하단 바의 주 동작 1개**가 항상 "다음에 할 일"이며, 확정 시 0.9초 로딩 후 다음 단계가 열린다.

### 3.3 ① 업로드

**여기서 이용자가 하는 일** — 직무발명서 PDF 1개를 올린다. 이것으로 이용자 입력은 끝이고 나머지는 추출 결과의 확인이다.

| 기능 요소 | 표시 기준 | 이용자 동작 → 결과 | 연결 API | SPC |

### 3.5 ③ 이미지 선별

**여기서 이용자가 하는 일** — 추출 이미지 중 **AI 맥락에 쓸 것을 "선택"**(B-06)하고 **대표 이미지 1개**를 지정한다. 미선택 이미지는 이후 생성에서 완전히 빠진다. 명세서 게재 여부(채택)는 ⑥에서 정한다.

### 3.12 도면 편집기 (새 탭 · 범위: 크롭 → CAD 변환)

**여기서 이용자가 하는 일** — 도면 1개씩 2단계: ⑴ **영역 확인** — 추출 BBox가 초기값으로 잡힌 크롭 박스를 조정하고 명칭·분류·캡션·변환 지시문을 다듬는다 ⑵ **CAD 변환** — 후보 3개(버전 A/B/C) 중 1개를 골라 **「✓ 이 버전으로 CAD 변환 완료」**. 완료 화면(초록 ✓)이 뜨고 메인 탭 도면 카드에 배지·변환본이 반영된다. 도면 편집(부호 배치)은 이번 버전 제외.

| 기능 요소 | 표시 기준 | 이용자 동작 → 결과 | 연결 API | SPC |
|---|---|---|---|---|
| 도면 목록(좌) | 도면별 진행 배지: 영역 확인·변환 중·후보 선택·`변환 완료`(초록) | 클릭 → 도면 전환 | — | (DRW-014 하위 — 새 탭 내부) |
| 영역 확인 | 원본 위 파란 크롭 박스(8핸들·이동·크기 %표시). **추출/조정 BBox가 초기값**, 좌표는 이미지 실제 크기 기준. 우측: 명칭·분류·캡션·`변환 지시문 (선택)` · `영역 초기화` | 「영역 확인 완료 — CAD 변환 시작」 | 요청에 `Drawing`+`bbox`(원본 px)+`user_instruction` | 〃 |
| CAD 변환·후보 선택 | 변환 중 스켈레톤 → 원본↔선택본 비교 + 하단 후보 3개(버전 A/B/C, 확대 보기) + `다시 변환`(지시문 수정) | 후보 클릭 → 「✓ 이 버전으로 CAD 변환 완료」 | `POST /generate/drawing/style-transfer`(`num_images=3`) → 후보 이미지 3개. `provider`·`quality`는 기본값 사용(UI 미노출 결정) | 〃 |
| 변환 완료 화면 | 초록 ✓ + "선택한 변환본이 명세서 도면에 반영되었습니다" + 변환본 미리보기 + `↻ 다시 변환 (영역부터)`/`완료 — 닫기` | — | 결과(BBox·명칭·분류·캡션·변환본)는 해당 작업의 도면에 반영 — 메인 화면이 열려 있으면 즉시, 아니면 재진입 시(전달 방식은 신규 설계) | DRW-015 연계 |

### 3.13 AI 수정 공통 규칙 (전 화면 동일)

모든 AI 수정은 **① 지시 입력 → ② 제안 카드 → ③ 적용/취소** — 즉시 반영은 없다(플래그 `AI_EDIT_CONFIRM`로 일괄 전환 가능). (공통 영역: WIZ-090)

| 기능 요소 | 표시 기준 | 이용자 동작 → 결과 | SPC |
|---|---|---|---|
| AI 수정(인라인) | 항목 우측 ✈ 버튼(호버 노출, 채택 항목만) → 지시 입력 카드(`수정 요청`/`취소`, Enter 전송·Esc 닫기) | 전송 → 제안 카드 | WIZ-091 |
| 전체 AI 수정 바 | 패널 상단 1줄: 지시 입력+`전체 AI 수정`. 제안 0건이면 "변경이 필요 없다고 판단했습니다" | 전송 → 채택 항목 전체 제안 | WIZ-092 |
| 제안 확인 카드 | 헤더(N건·지시사항) + 항목별 태그(수정/추가/삭제) + **Before/After 단어 diff**(삭제=빨강 취소선·추가=초록) + `✦ 설명` + `취소`/`적용` | 적용 → 반영+토스트 / 취소 → "수정을 적용하지 않았습니다" | WIZ-093 |

## 4. API 연동 맵 (역방향: API → 쓰는 곳)

| `POST /v2/extract/idf/drawing` | ① 업로드 | 페이지 이미지들 → ③ 이미지 목록(BBox는 썸네일 크롭·도면 편집기 크롭 초기값) |

| `…/embodiment-description` | ⑧ 명세서 생성(오버레이) | 확정 전체 → 에디터 「구체적 내용」 섹션 |

| `POST /chat/specification/assistant`(+`_stream`) | 에디터 AI 어시스턴트 | 명령+선택 단락 → intent별 응답(제안·플랜·교체·답변) |

**대표 시퀀스 — 위저드 한 단계(⑤→⑦)**: 확정(⑤) → `independent-claim/set` 요청 → 세트 선택 → `dependent-claim` 요청 → 채택·편집 → 확정(⑦) → `drawing-description` 요청(도면 설명 자동 생성).
**대표 시퀀스 — CAD 변환**: 도면 카드 ↗ → 새 탭(작업·도면·BBox 컨텍스트 전달) → 크롭 조정 → `style-transfer`(bbox·지시문·3장) → 후보 선택·완료 → 메인 화면 도면 카드에 변환 완료 배지+변환본 썸네일 반영(부재 시 재진입 때).

## 5. 저장·복원 (UI 요구만 — 구조는 신규 설계)

목업의 저장 방식은 설계 참고 대상이 아니다. UI가 요구하는 것만 정의한다:

- **자동 저장**: 저장 버튼·저장됨 표시가 없다. 모든 편집·확정·선택이 즉시 보존된다.
- **재진입 복원**: 작업을 다시 열면 떠났던 지점(단계·확정 내용·에디터 본문·화면 위치)부터 이어진다. 사이드바 배지(분석 중/명세서 생성완료)도 저장 상태에서 산출된다.
- **복원 범위 결정 필요(신규 설계 시)**: ⑦ 청구항의 중간 선택(세트 선택·종속항 채택·권리범위 설정), 구성요소 계층, AI 대화 이력 — 목업은 확정 텍스트만 유지하나, 서비스에서 어디까지 복원할지는 데이터 설계에서 정한다.
