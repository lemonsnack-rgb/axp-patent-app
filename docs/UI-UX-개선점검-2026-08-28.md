## 1. 디자인 심미성 개선사항

### D1. 타이포그래피 스케일 재정의 — P2
- **현상**: 12px(`xs2`)가 라벨·본문·버튼·안내문에 두루 쓰임. 카드 본문 textarea는 14px, 위저드 안내는 13px, 섹션 제목("발명의 설명")은 13px bold → **제목이 본문보다 작음**. 에디터에 9/10/11px 임의값 27곳.
- **제안**: 역할별 4단 고정 — 섹션 제목 15~16px semibold / 본문·입력 14px / 보조 설명 13px / 메타·배지 12px. **11px 이하 금지**(배지도 12px). Tailwind 임의값(`text-[10px]`) 제거.

### D2. Primary 색상 단일화 및 의미색 팔레트 정의 — P2
- **현상**: Primary CTA가 `brand-400`(#3B8EF5)·`blue-600`·`blue-700/800`으로 화면마다 다름. 순회 중 하단 "다음 →" 버튼이 2단계에서는 밝은 파랑, 3단계 이후엔 진한 남색으로 보임(클래스 `bg-brand-400 hover:bg-blue-800` — hover/포커스 잔상 여부 확인 필요). 에디터는 brand 1회뿐. 청구항 카테고리(purple), 플랜(violet), ACCEPT(emerald), 용어 교체(cyan), 표 캡션(gray) 등 의미색 6계열이 규약 없이 사용.
- **제안**: Primary = `brand-400/500`만. 의미색은 성공(green)·주의(amber)·위험(red)·정보(brand-50) 4종으로 축소하고, 카테고리 칩은 중립(gray) + 텍스트로 구분. 에디터 `bg-blue-600` 9곳 → brand.

### D3. 화면당 Primary 버튼 1개 원칙 — P1
- **현상**: 청구항 단계에 **풀폭 Primary "독립항 세트 생성 →"** + **풀폭 outline "선택한 세트로 종속항 구성 →"** + **하단 고정 "다음 →"** 3개가 동시 노출. 중간명세서 단계도 풀폭 남색 "명세서 생성 →"과 하단 바가 공존. 어느 버튼이 진행인지 시선이 분산됨.
- **제안**: 하단 고정 바의 "다음"이 단계 내 다음 동작을 **대신 수행**(라벨을 "독립항 세트 생성" → "종속항 구성" → "명세서 생성"으로 상황에 따라 변경)하거나, 단계 내 CTA를 Secondary로 내림.

### D4. 라운드·간격 토큰 규약 — P3
- **현상**: 같은 카드 안에 `rounded`(4px) 칩, `rounded-lg` 버튼, `rounded-xl` 카드, `rounded-2xl` 모달이 혼재. 카드 내부 패딩 p-2/p-2.5/p-3 혼용.
- **제안**: 컨테이너 `xl`, 컨트롤(버튼·입력) `lg`, 칩·배지 `md`. 카드 패딩 12px(p-3) 고정, 카드 간격 8px(space-y-2).

### D5. 아이콘 버튼 최소 크기 — P2
- **현상**: 에디터 단락 이동/삭제 20px, "수정모드 ↗" 18px, 위저드 순서 화살표 9px svg(패딩 포함 ~14px). 24px 미만 타깃 50개.
- **제안**: 아이콘 버튼 28×28(최소 24) + hover 배경. 화살표 svg 12px 이상.

### D6. 콘텍스트 폭·여백 — P3
- **현상**: 1707px 뷰포트에서 콘텍스트 열 768px, 좌우 각 ~340px 공백. 발명 설명 2컬럼은 각 ~400px로 표 항목이 세로로 늘어남. 우측 AI 패널(~360px)은 안내문 한 줄 외 비어 있음.
- **제안**: `max-w-3xl` → `max-w-5xl`(1024px) 또는 사이드바 접힘 시 확장. AI 패널은 기본 접힘 또는 §U12 컨텍스트 요약으로 채움.

### D7. 안내문 템플릿 반복 — P3
- **현상**: 8단계 모두 "업로드 내용을 기반으로 **X** 항목을 준비했습니다. 아래에서 확인하고 항목을 채우세요." + 완료 시 "X을 확정했습니다. Y를 생성합니다." 동일 문형. 정보 밀도가 낮고 스캔 시 구분이 안 됨.
- **제안**: 단계별 실질 안내 1문장(예: "채택할 항목만 체크하세요. 표 항목은 원문 그대로 반영됩니다.")으로 교체, 완료 문구는 접힌 요약 헤더로 대체(§U3).

## 2. UX/UI 개선사항

### U1. 하단 "다음"이 종속항 단계를 건너뜀 — **P1 (동작 오류)**
- **현상**: 청구항 단계에서 독립항 세트를 선택한 뒤 하단 고정 바의 "다음 →"을 누르면 **종속항 구성 없이 청구항이 확정**되어 중간명세서로 넘어감(실측). 코드상 하단 버튼이 `confirm(guideStep)`을 직접 호출([SpecView.tsx:764](../src/views/SpecView.tsx#L764))하고, 종속항 진입은 단계 내부 버튼 `confirmIndep`([SpecView.tsx:3005](../src/views/SpecView.tsx#L3005))에만 연결.
- **제안**: 청구항 단계에서 하단 "다음"은 (a) 종속항 미구성 시 비활성 + 툴팁 "세트를 선택하고 종속항을 구성하세요", 또는 (b) `claimsPhase`에 따라 "종속항 구성 →" / "청구항 확정 →"으로 위임. 데모는 종속항을 **별도 8단계**로 분리해 이 혼동이 없음 → 단계 분리도 검토.

### U2. 이미지 선별(3)과 명세서 도면(6)의 중복 선택 — P1
- **현상**: 같은 2장 이미지를 3단계에서 "선택/대표" 체크한 뒤, 6단계에서 다시 "선택"(초기 0개, 모두 "AI 참고용")을 체크해야 함. 두 단계의 차이("맥락용" vs "명세서 도면 채택")가 회색 한 줄 설명에만 있음. 6단계에 "건너뛰기"와 "다음"이 병존해 도면 0개로 진행 시 결과가 불명.
- **제안**: 6단계 기본값을 3단계 선택 상태로 프리셋(대표 이미지 = 도 1), 카드 배지를 "도 N 채택 / 참고만" 토글 하나로 통일, "건너뛰기" 제거(도면 0개면 "다음"에 확인 다이얼로그).

### U3. 누적 스크롤 + 하단 자동 스크롤 — P1
- **현상**: 단계 완료 시 이전 단계 전체가 그대로 남고 새 단계가 아래에 붙음. 자동 스크롤이 새 단계의 **하단(다음 버튼)**으로 가서 상단 도구(발명 설명 "전체 AI 수정" 바, 구성요소 "다시 분석·AI 추가·부호 자동 부여")가 시야 밖. 구성요소 단계는 첫 카드도 안 보이고 4번째 카드부터 보임.
- **제안**: 완료 단계는 **1줄 요약 아코디언**(예: "✓ 발명 설명 — 제안 4 · 종래 2 항목 채택 [펼치기]")으로 접고, 새 단계 **헤더**로 스크롤. 상단 스텝바는 유지.

### U4. 되돌아가기 경로 3중 — P2
- **현상**: 상단 스텝바(완료 단계 클릭), 각 단계 우측 "✎ 다시 선택", 하단 "← 이전"이 모두 존재. "다시 선택"이 이후 단계를 초기화하는지 알 수 없음.
- **제안**: 스텝바 클릭 = 보기 이동, "다시 선택" = 재확정(이후 단계 무효화 경고 다이얼로그) 1개로 통합, "← 이전"은 직전 단계로 스크롤만.

### U5. 독립항 세트 후보의 구분 불가 — P2
- **현상**: 생성된 세트 2개 모두 제목이 "균형 권리범위 — 등록 가능성과 보호 범위 균형"으로 동일. 청구항 전문을 읽어야 차이를 알 수 있음. 생성 후 결과가 화면 아래에 있어 "세트를 선택하세요" 버튼만 보임(스크롤 필요).
- **제안**: "세트 1 · 장치항+방법항 · 구성요소 4개" 식의 식별 라벨 + 세트 간 차이점 한 줄(AI 요약). 생성 직후 첫 세트로 스크롤.

### U6. 청구항 구성 슬롯 UI의 필수/선택 불명 — P2
- **현상**: "청구항 구성 (2/3)", purple "+ 청구항 추가", purple 카테고리 select, 회색 placeholder "이 청구항의 방향·강조점 (선택)", 하단 "추가 지시사항 (선택)" — 무엇을 반드시 해야 세트가 생성되는지 즉시 파악 안 됨. purple은 이 화면에서만 등장.
- **제안**: 기본 설정으로 바로 생성 가능함을 명시("기본값으로 바로 생성해도 됩니다"), 색은 brand로, 선택 필드는 접힘(고급 설정).

### U7. 발명 설명 카드 — "이동" 용어 중복·액션 분산 — P2
- **현상**: 카드 헤더 드래그 핸들에 "⠿ 이동"(순서 이동), 카드 하단에 "종래기술로 이동 →"(컬럼 이동) — 같은 단어가 다른 동작. 체크박스·핸들·라벨·↑↓·AI 수정이 헤더에, 컬럼 이동은 하단 우측에 흩어짐.
- **제안**: 핸들은 아이콘만(툴팁 "끌어서 순서 변경"), 컬럼 이동은 "종래기술로 보내기"로 명칭 변경 후 헤더 ⋯ 메뉴 또는 헤더 우측으로 이동. 표 항목 카드도 동일 헤더 구조 유지(현재 AI 수정만 빠져 정렬이 어긋남).

### U8. 이미지/도면 카드 액션 배치 — P2
- **현상**: "☑ 선택" 라벨형 체크(좌상단), "○ 대표" 라디오(우상단), "↗" 새 탭(좌상단 겹침), "삭제" 텍스트(하단 중앙), 분류 select(하단 좌) — 5개 컨트롤이 네 모서리에 분산.
- **제안**: 상단 = 선택 체크 + 대표 토글(한 줄), 하단 = 캡션 · 분류 · [↗][삭제] 아이콘 그룹.

### U9. 자동 생성 문장 오류 (도면의 간단한 설명) — P1
- **현상**: "**도 도면1은(는)** 시스템 전체 구성도**을(를)** 나타낸 도면이다." — symbol에 "도면1"이 들어가 "도 도면1"이 되고, 조사가 병기됨([SpecView.tsx:198](../src/views/SpecView.tsx#L198)). 중간명세서·에디터 본문에 그대로 노출.
- **제안**: 도 번호(숫자)만 사용 "도 1은", 조사 자동 선택(받침 유무) 유틸 적용.

### U10. 에디터 진입 시 맥락 단절 — P2
- **현상**: 에디터로 가면 스텝바가 사라지고 "← 분석 후보 보기"만 남음 — 위저드에서는 "단계", 여기서는 "분석 후보"로 용어 불일치. undo/redo 라벨이 "취소/재실행"(표준: "실행 취소/다시 실행"). 우측 AI 패널 안내 "중앙에서 단락을 선택하고 수정 명령을 입력하세요"인데 선택 수단(단락 좌측 회색 체크박스)이 눈에 띄지 않음.
- **제안**: "← 작성 단계로 돌아가기", 단락 hover 시 체크박스 강조 + 첫 진입 시 코치마크 1회, 툴바 라벨 표준화.

### U11. 좌측 작업 목록에 진행 단계 없음 — P2
- **현상**: 작업명(truncate) + 상대시간만 표시. 데모는 "제목·요약 / 중간명세서" 등 현재 단계를 표시해 이어하기가 쉬움.
- **제안**: 진행 단계 배지(예: "5/8 구성요소") 또는 진행 바 추가.

### U12. 위저드 우측 AI 어시스턴트 패널의 공백 — P2
- **현상**: 항목 수정을 인라인으로 옮긴 뒤 패널에는 안내문 1개만 남고 ~360px×전체 높이가 비어 있음(§D6). 데모는 같은 자리에 **InventionContext(지금까지 확정된 내용)** 요약을 표시.
- **제안**: 패널 상단에 "확정 내용 요약"(명칭·채택 항목 수·구성요소·도면·청구항 세트) 카드, 하단에 Q&A 입력. 또는 기본 접힘.

### U13. 개발용 토글 노출 — P3
- **현상**: 좌하단 "명세 모드 / 수집필드" 플로팅 버튼이 일반 사용자 화면에 상시 노출.
- **제안**: `?dev=1` 쿼리 또는 단축키로만 표시.

### U14. 새 명세서 진입 → 업로드 화면의 중복·덮어쓰기 — P3
- **현상**: NewTask 제목 "새 명세서 작성" 직후 업로드 화면 제목 "새 특허 명세서 작성"이 다시 나옴. NewTask에서 입력한 작업 이름이 업로드 시 **파일명으로 덮어써짐**(`setDiTitle(nameWithoutExt)`, [SpecView.tsx:423](../src/views/SpecView.tsx#L423)). 업로드 존에 파일 선택 버튼이 없어 클릭 가능 영역임을 점선만으로 표현.
- **제안**: 업로드 화면 제목 제거(스텝바가 맥락 제공), 작업 이름이 있으면 유지, 드롭존에 "파일 선택" 버튼 추가.

### U15. 발명 설명 2컬럼 헤더의 "N/N 선택" 의미 — P3
- **현상**: "제안기술 4/4 선택"의 "선택"이 채택(adopted)을 뜻하지만, 카드의 체크박스 a11y 이름은 "선택 해제"로 노출되어 스크린리더/툴팁 문구가 반대 상태를 말함.
- **제안**: "채택 4/4", 체크박스 라벨 "채택" (체크 시 "채택됨").

### U16. AI 수정 제안 카드 — 카드 폭·긴 문장 — P3 (이번 작업에서 추가된 UI)
- **현상**: 2컬럼(각 ~400px) 안에서 제목·"N건 · 지시사항: …"가 한 줄에 못 들어가 잘림(whitespace-nowrap 적용 후 지시사항이 truncate). Before(취소선)·After가 각각 전체 문장이라 카드가 길어짐.
- **제안**: 제안 카드는 컬럼을 벗어나 **카드 폭 = 컬럼 2개 합**으로 띄우거나, 단어 diff(에디터 `diffWords` 재사용)로 한 문장 안에서 변경부만 강조.
