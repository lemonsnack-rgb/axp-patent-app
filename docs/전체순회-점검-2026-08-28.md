## A. 오류 · 결함

### A1. 에디터 진입 시 AI 패널 입력창이 "단락 편집기"로 바뀌어 명령이 본문을 덮어씀 — **P1 (데이터 손상)** ✅ 반영
- **실측**: 에디터에 들어가면 첫 단락(기술분야 1)이 **자동으로 편집 모드**(파란 테두리 textarea)가 되고, 우측 AI 패널 헤더가 "기술분야 · 1 편집 중", 하단 입력창 placeholder가 **"단락 내용을 입력하세요..."**로 바뀜. 여기에 "이 단락을 더 구체적으로 써줘"를 입력하면 **기술분야 본문이 그 문장으로 교체**됨(미리보기에도 그대로 노출). 실행 취소로 복구는 가능.
- **문제**: 같은 위치·같은 모양의 입력창이 상황에 따라 "AI 명령"과 "본문 편집"으로 바뀜 — 사용자는 구분할 수 없음. 단락 체크 후에도 헤더가 "기술분야 · 2 편집 중"으로 표시되어 '편집'과 '선택'이 섞임.
- **원인(코드)**: 초기 선택이 `useState({ sid: 'technical_field', idx: 0 })`로 고정([SpecEditorView.tsx:472](../src/views/SpecEditorView.tsx#L472)) → 진입 즉시 편집 모드. 단일 선택 시 패널이 채팅 입력 대신 **본문 편집 textarea**를 렌더([SpecEditorView.tsx:1526](../src/views/SpecEditorView.tsx#L1526)).
- **제안**: (1) 초기 `sel = null`, (2) 패널 입력창은 **항상 AI 명령 전용**(단락 편집은 본문 textarea에서만), (3) 헤더 라벨 "선택 중 · 기술분야 1" + 선택 단락 미리보기 1줄.

### A2. 종속항이 독립항에 없는 구성요소를 "상기 ~"로 인용 (선행 근거 없음) — **P1 (내용 신뢰)** ✅ 반영(사용자 확정)
- **실측**: 청구항 1 구성요소는 데이터 수집부(100)·전처리부(200)·병렬 처리부(300)·결과 통합부(400)인데, 자동 생성된 종속항은 "제1항에 있어서, **상기 처리부**는 딥러닝…", "**상기 입력부**는 복수의 센서…", "**상기 출력부**…", "**상기 구성**은 클라우드…" — 인용 대상이 없음(antecedent basis 결함). 방법항(6항) 종속항도 "상기 처리부"로 장치 용어를 그대로 사용.
- **문제**: 변리사가 첫 화면에서 보는 청구항이 기본 문법을 어기면 도구 전체 신뢰가 떨어짐. 목업 데이터라도 시연 시 치명적.
- **제안**: (1) 종속항 mock을 독립항 `element_ids`의 용어(수집부/전처리부/병렬 처리부/결과 통합부)로 생성, 방법항은 "~하는 단계는" 문형, (2) **선행 근거 검증** — "상기 X"의 X가 인용 독립항에 없으면 카드에 경고 배지("'입력부'가 제1항에 없습니다").

### A3. 중간명세서 "다시 생성"이 확인 없이 편집 내용을 덮어씀 — P1 ✅ 반영
- **실측**: 블록 추가 후 "↻ 중간명세서 다시 생성" 클릭 → 다이얼로그 없이 즉시 재생성(데모는 `confirm("현재 편집 내용이 대체됩니다")`).
- **원인(코드)**: `regenerate()`가 즉시 실행([SpecView.tsx:3488](../src/views/SpecView.tsx#L3488)).
- **제안**: 편집 이력이 있으면 확인 다이얼로그, 또는 재생성본을 제안 카드(AiPendingCard)로 보여주고 적용.

### A4. 구성요소 "AI 추가" 결과가 지시문·안내문을 그대로 값으로 넣음 — P2 ✅ 반영(사용자 확정)
- **실측**: "온도 센서 추가" 입력 → 명칭 = **"온도 센서 추가"**, 정의 = **"온도 센서 추가 (AI 제안 — 영문명·상위어를 보완하세요)"**, 영문명·상위어 빈칸. 이 값이 그대로 부호(500)를 받고 청구항·명세서로 흘러감.
- **제안**: mock이라도 명칭/영문/상위어/정의를 분리 생성(예: 명칭 "온도 센서", 정의 "…의 온도를 측정하는 센서"), 미완 필드는 빈값 + 노란 "보완 필요" 배지, 보완 전에는 채택 해제 상태.

### A5. 이미지 0개·대표 미지정 상태로 진행 가능 — P2 ✅ 반영
- **실측**: 이미지 선별에서 전부 해제하고 "다음" → 경고 없이 진행. 대표 이미지도 미지정 상태로 진행 가능(이후 도면 프리셋이 첫 이미지를 대표로 잡아주기는 함).
- **제안**: 0개 시 "이미지 없이 진행" 확인 다이얼로그(도면·도면 설명이 비게 됨을 명시), 대표 미지정 시 첫 선택 이미지를 자동 대표로 표시.

### A6. 삭제 다이얼로그 조사 병기 — P2 ✅ 반영
- **실측**: '"시스템 전체 구성도"**을(를)** 목록에서 삭제하시겠습니까?' — `particle()` 유틸 미적용.
- **제안**: `showConfirm`/`openAlertDialog` 문구 전반에 `withParticle` 적용(다시 선택 경고 문구도 "을(를)" 사용 중).

### A7. 에디터 미리보기에 국내 명세서 표준 섹션 누락 — P3 (변리사) ✅ 반영
- **실측**: 【발명의 명칭】~【청구범위】까지는 있으나 **【요약】(요약서)·【부호의 설명】·【도면】** 없음. 제목·요약 단계에서 확정한 '개요'가 어디에도 반영되지 않음.
- **제안**: 요약 = 확정 개요 + 대표도 번호, 부호의 설명 = 구성요소 부호표 자동 생성, 도면 = 채택 도면 이미지. DOCX/PDF 내보내기도 동일 구조. *(반영: 에디터 섹션 '부호의 설명'(도면설명 뒤)·'요약'(청구범위 뒤) 추가, 저장본 마이그레이션, 미리보기 【도면】 이미지 + DOCX/PDF에 도면 전달)*

### A8. 청구항 인용 번호가 자동 갱신되지 않음 — P2 (변리사) ✅ 반영
- **실측**: 청구범위 섹션 안내 "번호는 위치에 따라 자동 부여됩니다. 본문의 '제N항' 참조는 자동 변경되지 않으니 직접 수정하세요." — 종속항 삭제·순서 변경 시 "제1항에 있어서" 인용이 깨질 수 있음을 사용자에게 떠넘김.
- **제안**: 종속 관계(`depends_on`)를 데이터로 유지하고 표시 시 번호를 계산(이미 위저드에서는 `fillParentNos`류 처리 중) — 에디터에서도 동일 로직 적용.

### A9. '직접 입력' 명칭 선택 시 개요(요약) 입력란 없음 — P2 ✅ 반영
- **실측**: 후보 카드는 명칭+개요 쌍인데 직접 입력은 명칭만. 데모는 명칭·개요 둘 다 직접 입력. 개요는 요약서(A7)의 원천.
- **제안**: 직접 입력 카드에 개요 textarea 추가(선택), 비어 있으면 AI 생성 버튼.

## B. UI/UX 개선

### B1. 제목·요약 카드의 "AI 수정" 2개가 세로로 연달아 붙어 있음 — P2 (사용자 지적) ✅ 반영
- **실측**: 명칭 행 우측 AI 수정과 개요 행 우측 AI 수정이 **6~7px 간격**으로 겹쳐 보임(3개 카드 모두). 어느 버튼이 무엇을 고치는지 라벨이 같아 구분 불가.
- **제안 A(권장, 데모 정합)**: 카드당 AI 수정 **1개**(우상단) — 데모처럼 "명칭·개요를 어떻게 수정할지" 한 번에 지시, 제안 카드에 명칭/개요 2건 표시. **제안 B**: 개요 버튼을 "개요" 라벨 옆 인라인 소형(텍스트 링크형)으로 내려 시각적으로 분리.

### B2. 종속항 목록의 "AI 수정 + ✕" 8쌍 반복 — P2 ✅ 반영
- **실측**: 종속항 8개 각 행 우측에 동일 버튼 2개 → 우측 열이 버튼 기둥처럼 보임. 종속항 텍스트 아래 여백도 커 카드당 ~110px.
- **제안**: 행 hover 시에만 노출(중간명세서 블록과 동일 규칙), 삭제는 ⋯ 메뉴 또는 체크 해제로 대체, textarea auto-height.

### B3. 발명 설명 카드 높이 과다 — P2 ✅ 반영
- **실측**: 본문 1~2줄인데 카드 ~160px(헤더 + rows=2 textarea + "종래기술로 보내기" 버튼 행). 한 화면에 열당 3장.
- **제안**: "보내기" 버튼을 헤더 우측(AI 수정 옆) 또는 ⋯ 메뉴로 올리고 textarea auto-height → 카드 ~90px.

### B4. 발명 설명 라벨 용어 — P2 (변리사) ✅ 반영
- **실측**: 라벨 4종 "배경기술 / 구현방법(표시 '구현') / 목적 / 효과". '구현'은 특허 문법 용어가 아니고 제안·종래 양쪽에 같은 라벨이 붙어 의미가 흐림.
- **제안**: 제안기술 = 목적(해결과제) · **구성(해결수단)** · 효과, 종래기술 = 배경기술 · **종래 구성** · 문제점. API 라벨(implementation 등)은 유지하고 표시명만 매핑.

### B5. 안내문 3중 — P3 ✅ 반영
- **실측**: 단계 안내(STEP_HINT) + 양 컬럼의 "카드를 끌어 순서 변경 · 아래 버튼으로 반대편 기술로 이동" 반복 + 헤더 카운트. 
- **제안**: 컬럼 안내는 제거(단계 안내에 이미 포함), 드래그 힌트는 핸들 툴팁으로.

### B6. 작은 클릭 타깃 잔존 — P2 ✅ 반영
- **실측**: 발명 설명 채택 체크박스 **16px**, 이미지 카드 '선택' 체크 14px, 이미지 '삭제' 텍스트 링크.
- **제안**: 체크박스 18~20px + 클릭 영역 24px(padding), 삭제는 아이콘 버튼 28px.

### B7. 용어 불일치 '선택' vs '채택' — P3 ✅ 반영
- **실측**: 발명 설명은 "채택 4/5", 이미지 선별은 "선택 2개", 요약 패널 "관련 이미지 2/2개 선택".
- **제안**: 이미지는 "사용"(맥락 사용) 또는 "선택"으로 통일하고 발명 설명·도면은 "채택" — 의미가 다르면 다르게, 같으면 같게.

### B8. 이미지 카드 썸네일 고정 높이 — P3 ✅ 반영
- **실측**: 썸네일 영역 ~380px 고정, 다이어그램은 중앙 200px → 빈 여백. 
- **제안**: `aspect-[4/3]` + `object-contain`, 최대 260px.

### B9. 요약 패널 "N단계" 표기 — P3 ✅ 반영
- **실측**: "지금까지 확정된 내용 0단계 / 5단계".
- **제안**: "확정 5 / 8" 진행 표기, 0일 때는 표기 생략.

### B10. 사이드바 배지로 메타 잘림 — P3 ✅ 반영
- **실측**: 배지 + 기술분야 + 시간이 한 줄에 못 들어가 "데이터 처리 · 1..."로 잘림.
- **제안**: 배지 우측 정렬(작업명 행) 또는 시간만 표시하고 기술분야는 툴팁.

### B11. 청구항 용어 도움말 부재 — P2 (대학원생) ✅ 반영
- **실측**: "추상화 수준 넓은/균형/한정", "장치항/방법항/제조항/조성물항", "권리범위" — 설명·툴팁 없음. 세트 카드 sub("등록 가능성과 보호 범위 균형")만 존재.
- **제안**: 각 옵션에 1줄 툴팁(예: 방법항 — "단계의 순서·동작으로 청구, 소프트웨어 발명에 유리"), 첫 진입 시 접힌 도움말 카드.

### B12. 에디터 청구범위 섹션의 상호작용 모델 불일치 — P2 ✅ 반영
- **실측**: 본문 단락은 클릭→편집, 체크→AI 대상인데 청구항은 **항상 textarea(편집 상태)**이고 체크박스가 없어 AI 수정 대상으로 선택 불가.

### B13. 도면 "범위 조정 · CAD 변환" 결과 상태 미표시 — P3 ✅ 반영
- **실측**: 새 탭에서 작업 후 카드에 변환 완료/미완 표시 없음.
