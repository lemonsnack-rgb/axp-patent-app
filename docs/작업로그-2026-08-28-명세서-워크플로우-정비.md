## 2. UI/UX 일관성 (사용자 지시)

원칙(메모리 `ui-consistency-rules`에도 기록):
1. 동일 역할 버튼은 동일 형태·유사 위치 — `AiEditButton`(항목 헤더 우측 끝, h-6, brand outline, 열림 시 brand 채움), `AiGlobalBar`(목록 상단, "전체 AI 수정")
2. 무의미 기호 라벨 금지 — 제목·요약 후보의 **A/B/C/D 배지 제거**, 라디오 + 명칭 텍스트가 곧 선택 라벨. "명칭" 라벨 행·"✓ 선택됨" 중복 제거로 카드당 2행 절약
3. 색상 brand(#3B8EF5, `brand-*`) 통일 — violet-600/blue-500 혼용 제거. 카테고리 칩(purple) 등 **의미 색상은 유지**. `@muhayu/axp-ui`·`index.css` 규약 범위 내
4. 중간명세서 블록: hover 세로 아이콘 열 → 가로 행 + 동일 AI 수정 버튼
5. 구성요소 'AI 추가' 버튼도 같은 스타일로

## 3. AI 수정 — 사람이 확인 → 적용 (사용자 결정: 전 위치 통일)

데모 실측 결과: 데모는 **항목별 AI 수정(발명 설명·명칭·구성요소)은 즉시 반영**, **전체 수정·독립항·종속항·에디터 제안은 pending 카드로 확인 후 적용**(`renderPendingInto`, ACCEPT/DECLINE). 우리 목업은 전부 즉시 반영이었음 → 사용자가 **모든 위치를 확인 단계로 통일**하기로 결정.

구현:
- `PendingChange { tag, label, before, after, explanation, apply }` + `proposeMock()`
- `AiPendingCard` — 제목 · N건 · 지시사항 · [수정/추가/삭제] 태그 · Before(취소선)/After · ✦설명 · [취소][적용] (데모 카드 정합)
- `InlineAiEdit(original, label, onApply, doneMsg)` — 내부에서 제안 생성 → 카드 → 적용/취소(취소 시 입력창 복귀)
- `AiGlobalBar(propose, onApply?, title, doneMsg)` — 제안 0건이면 "변경이 필요 없다고 판단했습니다"
- 호출부: 인라인 8곳(명칭·개요·발명설명·구성요소·독립항×2·종속항·중간명세서 블록), 전체 3곳(발명 설명·구성요소·종속항)
- **`AI_EDIT_CONFIRM` 플래그 하나로 즉시 반영 회귀 가능** (호출부 무수정)

데모와 다른 점(기능정의서 갱신 시 표기 필요):
- 항목별 AI 수정에 확인 단계 추가 (데모: 즉시 반영)
- 중간명세서 블록별 AI 수정은 데모에 없음 (데모: 전체 재생성만)
