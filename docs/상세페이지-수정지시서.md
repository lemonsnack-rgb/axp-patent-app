## 1. 문헌종류 — 코드 대신 라벨

**현재**: `문헌종류  B1`
**수정**: `문헌종류  등록특허공보`

```ts
const DOC_KIND_LABEL: Record<string, string> = {
  B1: '등록특허공보',   // 1,801건
  Y1: '등록실용신안공보', // 3건
};
const 문헌종류 = DOC_KIND_LABEL[document_kind] ?? document_kind;  // 미관측 코드는 원값
```

- **추정 매핑 금지**: 현재 적재는 등록계뿐이라 `A`(공개특허공보)·`U`(공개실용신안공보)는 **한 건도 관측되지 않았다.** 공개 문헌 적재 후 도메인을 확인해 확장한다
- 근거: `document_kind` ↔ 문헌번호 접두 대조 불일치 0건(`B1`↔`10-`, `Y1`↔`20-`)

| 확인용 문헌 | 현재 | 수정 후 |
|---|---|---|
| `KR 10-2620137 B1` | `B1` | `등록특허공보` |
| `KR 20-0497874 Y1` | `Y1` | `등록실용신안공보` |

## 3. 공개/공고 — 라벨 교체 + 값 자리 교환 ★

**왜**: 「공개」와 「공고」는 다른 사건이다. 현재는 **공개번호 옆에 공고일**이 붙어 짝이 어긋난다(985건).

```
현재
  문헌번호       KR 10-2620137 B1    문헌일        2023-08-29   ← 값은 공개일인데 라벨이 모호
  공개/공고번호  10-2023-0126008     공개/공고일   2024-01-02   ← 번호는 공개, 일자는 공고

수정 (행 수 동일 · 새 행 없음)
  문헌번호       10-2620137 B1       공고일        2024-01-02   ← publication_date
  공개번호       10-2023-0126008     공개일        2023-08-29   ← open_date · 짝이 맞음
```

**계열 라벨은 번호 형식으로 판정한다.**

```ts
function pubSeriesLabel(no: string): string {
  if (/^\d{2}-\d{4}-\d{7}$/.test(no)) return '공개번호';      // 985건 (짝: open_date)
  if (/^WO \d{4}\/\d{6}$/.test(no))   return '국제공개번호';  // 113건 (짝: open_date)
  if (/^\d{2}-\d{7}$/.test(no))       return '공고번호';      // 314건 (등록번호와 값 동일)
  return '공개번호';
}
```

| 확인용 문헌 | 현재 | 수정 후 |
|---|---|---|
| `KR 10-2620137 B1` | `공개/공고번호 10-2023-0126008` + `공개/공고일 2024-01-02` | `공개번호 10-2023-0126008` + `공개일 2023-08-29` · `공고일 2024-01-02` |
| `KR 10-2635013 B1` | `공개/공고번호 WO 2011/146808` + `공개/공고일 2011-11-24` | `국제공개번호 WO 2011/146808` + `공개일 2011-11-24` |

**주의**: `publication_date`에 공고일이 아닌 값이 섞인 문헌이 있다(`KR 20-0497874 Y1` = `2023-04-05`로 등록일 `2024-03-18`보다 앞섬). **라벨을 번호 계열에서 유도**해야 이런 값이 드러난다.

## 7. 청구범위 — 삭제항 제외 ★ 최우선

**왜**: 심사 중 취하돼 본문이 **「삭제」 한 단어**인 항이 4,323개 있다(1,237문헌·68%). 이 항들은 **전건 `depends_on`이 없어** 현재 규칙에서 **「독립항」으로 분류**된다.

- 「독립항」 목록에 권리 없는 빈 항이 섞인다
- 서지 「청구항 수」(=삭제 제외 실질 수)와 목록 개수가 **한 페이지에서 다르게** 보인다 — 1,245문헌
- 「독립항 / 전체청구항」 토글이 **같은 결과**를 내는 문헌이 309개

```ts
const isDeleted = (t: string) => /^\s*삭제\s*\.?\s*$/.test(t);

const alive   = claims.filter(c => !isDeleted(c.text));
const deleted = claims.filter(c =>  isDeleted(c.text));

독립항 모드 = alive.filter(c => !c.depends_on)
전체 모드   = alive                      // 기본
표시        = 위 + 「삭제된 청구항 N개」 접기(펼치면 항 번호만)
```

- 이렇게 하면 서지 「청구항 수」와 목록 개수가 **정의상 일치**한다(`claim_count`는 이미 삭제 제외 수 — 1,778건 98.6% 검증)
- **접기 UI 1개 추가**가 필요하다. 삭제항을 그냥 빼면 항 번호가 `1,3,4,6…`처럼 건너뛰어 사용자가 결손으로 오해한다

| `KR 10-2620415 B1` | 독립항 **46개**(45개 본문 `삭제`) · 토글 양쪽 동일 · 서지 `1개` | 독립항 **1개**(제20항) + 「삭제된 청구항 45개」 접기 |

## 8. 패밀리정보 — 국가 탭 · 실제 집계 · 중복 제거

**현재**: 국가 구분 없이 번호만 평면 나열. 같은 문헌이 두 줄로 보이는 문헌이 195개.
**수정**: 국가 탭 + 국가별 건수(기획안에 있던 기능) + 정규화 후 집계.

```ts
// 국가 = 패밀리 문헌번호 앞 2자 (실데이터 6,427건 전건 보유)
// 중복 = 선행 0 패딩만 다른 같은 문헌 → 정규화 키로 합친다. 종류코드가 다르면 다른 문헌이다.
function familyKey(country: string, docNumber: string): string {
  const m = docNumber.trim().match(/^([A-Z]{2}\s*)?([A-Z]*)\s*0*([0-9][0-9-]*)\s*(.*)$/);
  return m ? `${country}|${m[2]}|${m[3].replace(/-/g, '')}|${m[4]}` : `${country}|${docNumber}`;
}
국가별 건수 = COUNT(DISTINCT familyKey) GROUP BY 국가
전체        = 국가별 합계          // family.document_count 는 중복 포함이라 쓰지 않는다
```

- 목록에 **명칭·출원일 열은 만들지 않는다** — 두 필드는 채움률 0%다
- 적재 측 중복(F-15)이 고쳐지기 전까지 **화면에서 정규화**한다

| 확인용 문헌 | 현재 | 수정 후 |
