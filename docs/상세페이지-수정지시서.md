## 1. 문헌종류 — 코드 대신 라벨

**위치**: 서지사항 `#bibliographic` → 라벨 `문헌종류` 행 → **2번째 칸** (같은 행 오른쪽은 `권리상태`, 건드리지 않음)


**현재**: `문헌종류  B1`
**수정**: `문헌종류  등록특허공보`

```ts
const DOC_KIND_LABEL: Record<string, string> = {
  B1: '등록특허공보',   // 1,801건
  Y1: '등록실용신안공보', // 3건
};
const 문헌종류 = DOC_KIND_LABEL[document_kind] ?? document_kind;  // 미관측 코드는 원값
```

- **추정 매핑 금지**: 현재 적재는 등록계뿐이라 `A`(공개특허공보)·`U`(공개실용신안공보)는 **한 건도 관측되지 않았다.** 공개 문헌 적재 후 도메인을 확인해 확장한다
- 근거: `document_kind` ↔ 문헌번호 접두 대조 불일치 0건(`B1`↔`10-`, `Y1`↔`20-`)
- 실데이터는 `document_kind` 채움률 100%라 **폴백이 필요 없다.** (목업에는 코드가 없는 데모 문헌이 있어 상태 기반 폴백을 남겨 뒀다 — 구현에는 넣지 않는다)

| 확인용 문헌 | 현재 | 수정 후 |
|---|---|---|
| `KR 10-2620137 B1` | `B1` | `등록특허공보` |
| `KR 20-0497874 Y1` | `Y1` | `등록실용신안공보` |

## 3. 공개/공고 — 라벨 교체 + 값 자리 교환 ★

**위치**: 서지사항 `#bibliographic` → `문헌번호` 행(0)의 **3·4번째 칸**, `공개/공고번호` 행(2)의 **1·3번째 칸** — 두 행만 손댄다


**왜**: 「공개」와 「공고」는 다른 사건이다. 현재는 **공개번호 옆에 공고일**이 붙어 짝이 어긋난다(985건).

```
현재
  문헌번호       KR 10-2620137 B1    문헌일        2023-08-29   ← 값은 공개일인데 라벨이 모호
  공개/공고번호  10-2023-0126008     공개/공고일   2024-01-02   ← 번호는 공개, 일자는 공고

수정 (행 수 동일 · 새 행 없음)
  문헌번호       10-2620137 B1       공고일        2024-01-02   ← publication_date
  공개번호       10-2023-0126008     공개일        2023-08-29   ← open_date · 짝이 맞음
```

**계열 라벨은 번호 형식으로 판정한다.**

```ts
function pubSeriesLabel(no: string): string {
  if (/^\d{2}-\d{4}-\d{7}$/.test(no)) return '공개번호';      // 985건 (짝: open_date)
  if (/^WO \d{4}\/\d{6}$/.test(no))   return '국제공개번호';  // 113건 (짝: open_date)
  if (/^\d{2}-\d{7}$/.test(no))       return '공고번호';      // 314건 (등록번호와 값 동일)
  return '공개번호';
}
```

| 확인용 문헌 | 현재 | 수정 후 |
|---|---|---|
| `KR 10-2620137 B1` | `공개/공고번호 10-2023-0126008` + `공개/공고일 2024-01-02` | `공개번호 10-2023-0126008` + `공개일 2023-08-29` · `공고일 2024-01-02` |
| `KR 10-2635013 B1` | `공개/공고번호 WO 2011/146808` + `공개/공고일 2011-11-24` | `국제공개번호 WO 2011/146808` + `공개일 2011-11-24` |

**주의**: `publication_date`에 공고일이 아닌 값이 섞인 문헌이 있다(`KR 20-0497874 Y1` = `2023-04-05`로 등록일 `2024-03-18`보다 앞섬). **라벨을 번호 계열에서 유도**해야 이런 값이 드러난다.

## 5. 현재 비어 있는 항목 — 표시 방식 결정 필요 (서지 5 + 인명 2)

> **채움률 0%는 「불필요」가 아니다.** 지금 적재분이 KR 등록건뿐이라 비어 있을 뿐, 앞으로 값이 들어올 수 있는 필드다.
> **필드·라벨 정의는 그대로 두고**, 값이 없는 동안의 표시 방식만 정한다. 어느 쪽을 택하든 **값이 들어오면 자동으로 노출**되어야 한다.

**위치**: 서지사항 `#bibliographic`의 `권리변동`·`최종처분상태`·`출원구분`·`실시권 등록일`·`지정국` 칸 + 인명정보 `#person`의 `특허고객번호 (KR)`·`심사관` 행

**대상**: 아래 7개는 **현재 적재분 1,804건에서 전건 비어 있다.** 지금은 모두 `—`로 자리만 차지한다.

**선택지** — 결정 후 구현한다.

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 조건부 숨김** (목업 반영본) | 값이 없으면 라벨 칸까지 비우고, 좌·우가 모두 비면 행 미렌더 | 빈 `—` 7행이 사라져 실제 정보가 눈에 들어옴 | 화면에 어떤 항목이 있는지 사용자가 알 수 없음 |
| **B. 현행 유지(`—`)** | 라벨과 `—`를 그대로 노출 | 수집 예정 항목을 사용자가 인지 | 7행이 빈칸으로 자리 차지 |
| **C. 절충** | 서지 5행은 숨기고, 값이 들어올 예정임을 한 줄 안내 | — | 안내 문구 추가 필요 |

```tsx
// 목업 BibRow 참고 — 빈 칸도 <td>로 자리를 유지해 4칸 정렬이 깨지지 않게 한다
if (hideEmpty && blank(v) && blank(v2)) return null;
const showL = !hideEmpty || !blank(v);
const showR = !hideEmpty || !blank(v2);
```

## 7. 청구범위 — 삭제된 청구항 처리 ⛔ **결정 대기 · 구현 보류**

> **처리 방식은 변리사 확인 후 결정한다.** 아래 A안은 목업에 잠정 반영했을 뿐 확정이 아니다.
> 권리 범위 해석에 직결되는 사안이라 임의로 정하지 않는다. 상용 서비스(윕스온 등) 표기도 함께 참고한다.
> **확정 전까지 개발 구현은 보류한다.**

**위치**: 청구범위 `#claims` → 항 라벨(`독립항 — 제N항` / `종속항 (제N항 → 제M항 인용)`)과 본문, 그리고 상단 토글 버튼 `독립항`·`전체청구항`

**확인해야 할 것**

1. 삭제된 청구항을 목록에서 **빼는 것이 맞는가**, 아니면 「삭제」로 **남겨 보여주는 것이 맞는가**
2. 남긴다면 **독립항 분류에서만 빼면 되는가** (현재는 독립항으로 표시된다)
3. 서지 「청구항 수」(삭제 제외 수)와 목록 개수를 **어느 쪽 기준으로 맞출 것인가**

| 안 | 목록 | 독립항 토글 | 서지 숫자와 |
|---|---|---|---|
| **A** (목업 잠정) | 삭제항 제외 + 「삭제된 청구항 N개」 접기 | 실질 독립항만 | 일치 |
| **B** | 삭제항을 「삭제」 라벨로 목록에 남김 | 독립항 분류에서 제외 | 불일치(목록이 많음) |
| **C** (현행) | 전부 노출 | **삭제항이 독립항으로 표시** | 불일치 |

**아래는 확정 사실(안 선택과 무관)** — 판단 근거로만 쓴다.

**왜**: 심사 중 취하돼 본문이 **「삭제」 한 단어**인 항이 4,323개 있다(1,237문헌·68%). 이 항들은 **전건 `depends_on`이 없어** 현재 규칙에서 **「독립항」으로 분류**된다.

- 「독립항」 목록에 권리 없는 빈 항이 섞인다
- 서지 「청구항 수」(=삭제 제외 실질 수)와 목록 개수가 **한 페이지에서 다르게** 보인다 — 1,245문헌
- 「독립항 / 전체청구항」 토글이 **같은 결과**를 내는 문헌이 309개

```ts
// 삭제항 판별식은 어느 안을 택하든 동일하다
const isDeleted = (t: string) => /^\s*삭제\s*\.?\s*$/.test(t);

// A안 예시 (목업 잠정 반영)
const alive   = claims.filter(c => !isDeleted(c.text));
const deleted = claims.filter(c =>  isDeleted(c.text));
독립항 모드 = alive.filter(c => !c.depends_on)
전체 모드   = alive + 「삭제된 청구항 N개」 접기
```

- `claim_count`는 **삭제 제외 실질 항 수**다(1,778건 98.6% 검증) → A안을 택하면 서지 숫자와 목록이 정의상 일치한다
- 삭제항을 그냥 빼면 항 번호가 `1,3,4,6…`처럼 건너뛴다 → **접기 등 보완 표시가 필요**하다

| 확인용 문헌 | 현재 | 수정 후 |
|---|---|---|
| `KR 10-2620415 B1` | 독립항 **46개**(45개 본문 `삭제`) · 토글 양쪽 동일 · 서지 `1개` | A안: 독립항 **1개**(제20항) + 접기 45개 |
| `KR 10-2619202 B1` | 독립항 8개 중 제2·7항이 `삭제` | A안: 독립항 6개 + 접기 2개 |

## 8. 패밀리정보 — 국가 탭 · 실제 집계 · 중복 제거

```ts
// 국가 = 패밀리 문헌번호 앞 2자 (실데이터 6,427건 전건 보유)
// 중복 = 선행 0 패딩만 다른 같은 문헌 → 정규화 키로 합친다. 종류코드가 다르면 다른 문헌이다.
function familyKey(country: string, docNumber: string): string {
  const m = docNumber.trim().match(/^([A-Z]{2}\s*)?([A-Z]*)\s*0*([0-9][0-9-]*)\s*(.*)$/);
  return m ? `${country}|${m[2]}|${m[3].replace(/-/g, '')}|${m[4]}` : `${country}|${docNumber}`;
}
국가별 건수 = COUNT(DISTINCT familyKey) GROUP BY 국가
전체        = 국가별 합계          // family.document_count 는 중복 포함이라 쓰지 않는다
```

- 목록에 **명칭·출원일 열은 만들지 않는다** — 두 필드는 채움률 0%다
- **목록과 집계에 같은 정규화 키를 쓴다** — 탭 숫자는 7인데 목록은 8줄인 상태가 되지 않도록 한다
- 적재 측 중복(F-15)이 고쳐지기 전까지 **화면에서 정규화**한다

## 13. 확인했으나 수정 불필요

개발서버가 이미 실데이터 구조와 맞는 항목이다. 건드리지 않는다.

| 항목 | 확인 내용 |
|---|---|
| 행정처리(수발신) | 수집은 **최신 1건 단일 객체**(1,200건 전건). 현재 화면도 1건 표시 — 이력 목록으로 바꾸지 말 것 |
| 심판 정보 | 종류·상태·번호 3필드 구조가 데이터와 일치(10건) |
| 우선권 주장 | 우선권주장일이 있는 문헌은 `priorities` 배열도 채워져 있다(결손 0건) |
| 존속기간(예상)만료일 | 전건 `등록일 + 20년` 계산 일치 |
| 인용·피인용 | 명칭은 수집 컬럼이 없어 표시하지 않는 현재 처리가 맞다(이번 범위 제외) |
| 발명자 주소 축약 | 전원 주소가 같으면 1줄, 다르면 `이름 — 주소` — 정보 손실 없음(정상) |

**데이터가 없어 자동으로 숨겨지는 블록**(코드 수정 불필요): 권리이전 이력 · 표준특허 · 국가별 추가정보(US 관련출원·가출원, JP 공보판, EP 언어) — 모두 현재 0건이며 조건부 렌더로 처리하면 된다.
**단, 국가 R&D 정보는 수집 필드 자체가 없다**(`meta_json`에 키 없음) → 화면에서 뺄지 결정 필요.
