## 1. P0 — 치명

### F-01
**국가 필터에서 `DE 독일`·`GB 영국`을 선택해도 무시되고 한국 문헌이 반환됨** (BUG-001 / TC-PAT-INP-014)

**재현 절차**
1. `/patent-front/patents?lang=ko` 진입 → `초기화`
2. 검색식 `자동차`, `기간`=`전체` 설정
3. `국가` `전체` 클릭 후 `DE 독일`만 선택 → `검색`
4. `GB 영국`으로도 반복

**현재 상태**

| 국가 | URL 값 | 건수 | 상위 행 |
|---|---|---|---|
| JP·CN·EP | `countries=JP` 등 | 0건 | — |
| PCT | `countries=WO` | 0건 | — |
| **DE** | `countries=DE` | **158,490건** | `1019830008862 A` (한국 문헌) |
| **GB** | `countries=GB` | **158,490건** | `1019830008862 A` (한국 문헌) |

158,490건은 `countries` 미지정(KR·US 기본) 결과와 같은 값입니다. 즉 DE·GB는 필터가 적용되지 않고 전체 결과가 그대로 나옵니다.

**기대 결과**
선택한 국가의 문헌만 반환. 해당국 적재분이 없으면 `0건` + E0 안내.

**수정해야 할 사항**
- `POST /api/service/axp/patent-searches` 페이로드의 `countries[]`에 `DE`/`GB`가 실려 나가는지, 서버가 이 두 코드를 인식하는지 확인
- 미지원 국가 코드가 들어왔을 때 **필터를 무시하고 전체를 반환하는 fallback을 제거**. 인식 불가 코드는 빈 결과 또는 명시적 오류로 처리
- JP·CN·EP·PCT는 정상이므로 코드 매핑 테이블에서 DE·GB 누락 여부를 우선 확인 (PCT→`WO` 매핑은 정상 동작 중)

**검증 방법**
DE·GB 단독 선택 시 건수가 KR·US 기본 결과(158,490)와 **달라야** 합니다. 0건이어도 통과입니다.

### F-02
**`분류코드 검색 대상`을 `Current Only`로 바꾸면 검색이 실패함** (BUG-002 / TC-PAT-INP-022)

**재현 절차**
1. `초기화` → `항목별 상세검색` 펼침
2. `IPCM`에 `G06F*` 입력, `분류코드 검색 대상`=`Original or Current`(기본)로 `검색` → 정상
3. `Current Only`로 변경 후 `검색`

**현재 상태**

| 옵션 | 조립된 검색식 | 결과 |
|---|---|---|
| `Original or Current` | `IPCM:(G06F*)` | 1,253,662건 정상 |
| **`Current Only`** | **`IPCCM:(G06F*)`** | **V3 `검색에 실패했습니다.`** |

`IPCCM`은 필드코드 카탈로그(`+ 검색 필드 추가·확장` 82필드)에 존재하지 않는 코드입니다. 2026-08-10 실측 시에는 `IPCM:(G06F*) AND IPCCM:(G06F*)`로 조립됐고, 현재는 `IPCCM` 단독으로 바뀌었으나 **실패 원인은 동일**합니다.

**기대 결과**
`Current Only` 선택 시에도 정상 결과 반환. `Original or Current` 대비 건수가 같거나 적어야 합니다(부분집합).

**수정해야 할 사항**
- `POST /api/service/axp/patent-search-queries/composition`이 `Current Only`에 대해 생성하는 코드를 확인. 서버가 실제로 지원하는 코드로 교체
- 지원 코드가 없다면 옵션 자체를 비활성화하거나, 필드절이 아닌 **검색 파라미터**로 전달하는 방식으로 변경
- `CPCM`에도 같은 옵션이 있으므로 함께 점검

**검증 방법**
`IPCM`+`Current Only`, `CPCM`+`Current Only` 둘 다 V3 없이 결과 반환. 조립된 검색식의 코드가 카탈로그 82필드 안에 있을 것.

## 2. P1 — 중대

### F-03
**기간 프리셋 — 기본값 미적용 · `datePreset` 누락 · `최근 5년` 0건** (BUG-003·014·025 / TC-PAT-INP-016)

**재현 절차**
1. `초기화` (기간이 `최근 5년`으로 표시됨) → 검색식 `자동차` → `검색`
2. 이어서 `전체`·`최근 5년`·`최근 10년`·`최근 20년`을 각각 **명시 클릭**해 `검색`

**현재 상태**

| 조작 | URL | 건수 |
|---|---|---|
| 초기화 직후(표시 `최근 5년`) | `?lang=ko&query=자동차` — 일자 파라미터 **없음** | 158,490 |
| `전체` 명시 클릭 | `datePreset=ALL` | 158,490 |
| `최근 5년` 명시 클릭 | `dateFrom=2021-08-11&dateTo=2026-08-11` — **`datePreset` 없음** | **0** |
| `최근 10년` | `dateFrom=2016-08-11&dateTo=2026-08-11&datePreset=Y10` | 9,224 |
| `최근 20년` | `dateFrom=2006-08-11&dateTo=2026-08-11&datePreset=Y20` | 40,067 |

세 가지 문제가 겹쳐 있습니다.
1. **기본값이 표시만 되고 쿼리에 실리지 않음** — 사용자는 `최근 5년`으로 좁혀졌다고 믿지만 전체 기간 결과를 봅니다
2. **`최근 5년`만 `datePreset` 파라미터가 누락** — 다른 프리셋과 직렬화 규칙이 다름
3. **`최근 5년` 결과가 0건** — 출원일 최신 정렬 1위가 `2019-04-08`이므로 2021년 이후 적재분이 없는 것으로 보입니다

**기대 결과**
- 초기화 직후 검색에도 표시된 기간이 그대로 적용
- 프리셋 4종의 URL 직렬화 규칙 일치
- 적재 범위 안에서 `최근 5년` ⊆ `최근 10년` ⊆ `최근 20년` ⊆ `전체` 단조 관계 성립

**수정해야 할 사항**
- 초기 상태의 기간 값을 검색 payload에 포함 (또는 기본값을 `전체`로 바꾸고 표시도 맞춤 — **어느 쪽인지 기획 확정 필요**)
- `최근 5년`에도 `datePreset=Y5` 부여
- 3번은 **데이터 적재 이슈일 가능성이 높으므로 별도 확인 요청**드립니다. 프론트 수정 대상이 아니라면 회신 부탁드립니다

**검증 방법**
초기화 직후 검색 URL에 일자 파라미터가 포함될 것. 프리셋 4종 모두 `datePreset` 보유. 건수 단조성 성립.

### F-04
**상태 축 — 라벨 중복·오매핑과 패싯 `공개` 미적용** (BUG-004 · BUG-028 · 신규 N-13 / TC-PAT-INP-019 · TC-PAT-LST-005)

> **2026-08-12 추가 측정으로 원인이 확정되었습니다.** 상단 `상태`와 좌측 `권리상태`는 **같은 축**입니다. 두 파라미터 모두 서버 payload의 동일한 `statuses[]` 필드로 수렴합니다. 처분관점/등록관점이 섞인 것이 아니라, **하나의 `register_status` 축에 두 벌의 라벨이 붙어 있는 것**이 문제입니다.

**측정 근거** (검색식 `하이브리드 and 자동차`, 기간=전체, 총 1,684건)

| 조작 | 서버 payload | 건수 | 결과 표 `상태` 컬럼 |
|---|---|---|---|
| 상단 `등록` | `{"statuses":["REGISTERED"]}` | 725 | 등록 |
| 좌측 패싯 `등록` | `{"statuses":["REGISTERED"]}` | 725 | 등록 |
| 상단 `출원` | `{"statuses":["APPLIED"]}` | **180** | **공개** |
| 상단 `심사중` | `{"statuses":["UNDER_EXAMINATION"]}` | **180** | **공개** |
| 좌측 패싯 표기 | — | `공개 (180건)` | — |
| **좌측 패싯 `공개` 적용** | **`statuses` 키 누락** | **1,684 (전체)** | 거절·등록·공개·취하·소멸 혼재 |

**현재 상태 — 세 가지 문제**

1. **상단 `출원`·`심사중`이 같은 데이터를 가리킴.** 서로 다른 코드(`APPLIED` / `UNDER_EXAMINATION`)로 나가지만 서버에서 같은 집합으로 매핑되어 건수·상위 행이 완전히 동일합니다 (BUG-004의 확정된 원인)
2. **상단 라벨이 실제 값과 다름.** `출원`·`심사중`으로 필터하면 결과 표 `상태` 컬럼에는 `공개`가 표시됩니다. 즉 두 라벨 모두 `register_status = 공개`를 가리킵니다
3. **좌측 패싯 `공개`를 적용하면 필터가 무시됨** (신규 N-13). 패싯은 `공개 (180건)`으로 표기해 놓고, 클릭·`적용` 시 payload에서 `statuses`가 통째로 빠져 전체 1,684건이 반환됩니다. `등록`은 `REGISTERED`로 정상 변환되는데 `공개`만 대응 코드로 변환되지 못하고 드롭됩니다 — BUG-001(DE·GB 무시)과 같은 "필터가 조용히 무시되는" 계열

**해소된 항목** — 상단에만 있던 `무효`는 정상 값입니다 (`INVALIDATED`, 24건, 상태 컬럼 `무효`). 좌측 패싯에 안 보였던 것은 해당 검색 결과에 무효 문헌이 없었기 때문이며, 패싯은 결과 내 분포만 표시하므로 **결함이 아닙니다.** BUG-028의 "값 집합 불일치" 중 이 부분은 철회합니다.

**기대 결과**
상단·좌측·목록 컬럼이 모두 같은 `register_status` 어휘를 쓰고, 어떤 값으로 필터해도 적용됨.

**수정해야 할 사항**
- **[필수] 좌측 패싯 `공개` → `APPLIED` 매핑 추가.** 현재 드롭되는 유일한 값입니다
- **[필수] 상단 `출원`·`심사중`을 `공개` 하나로 통합.** 실측상 두 코드가 같은 집합이므로 UI에 둘로 노출할 근거가 없습니다. 서버에서 정말 구분되어야 한다면 `UNDER_EXAMINATION`이 별도 집합을 반환하도록 수정
- **[권고] 라벨 정리** — 값 집합이 `등록·공개·거절·소멸·취하·포기·무효` 7종이므로 `공개`를 포함할 수 있는 이름이어야 합니다

| 대상 | 현재 | 권고 | 상태 |
|---|---|---|---|
| 입력 필터 `문헌종류` | `공개` · `등록` | `공개특허공보` · `등록특허공보` | **별도 요청 완료 (2026-08-12)** |
| 목록 컬럼 헤더 | `상태` | `등록상태` (상단 필터와 구분) | 미요청 |
| 좌측 패싯 | `권리상태` | `등록상태` — 공개 단계에는 권리가 없으므로 "권리"는 부정확 | 미요청 |
| 상단 필터 | `상태` (출원·심사중 중복) | `등록상태`, 값은 7종으로 통일 | 미요청 |
| 상단 A/I 그룹 | A: 출원·심사중·등록 / I: 거절·소멸·취하·포기·무효 | A: **공개**·등록 / I: 거절·소멸·취하·포기·무효 | 미요청 |

> `문헌종류` 라벨이 `공개특허공보`/`등록특허공보`로 바뀌면 **문헌종류 축과 상태 축 사이의 `공개`·`등록` 단어 충돌은 해소**됩니다. 남는 것은 상태 축 내부의 라벨 정리(위 4행)입니다.
> 함께 확인: 목록 문헌번호 접미의 `A`/`B1`은 `document_kind` 값이므로(`문헌번호 = country_code + 번호 + document_kind`), 새 라벨과 의미가 일치하는지 봐 주세요 — `A`=공개특허공보, `B1`=등록특허공보.

**검증 방법**
- 좌측 패싯 `공개 (N건)` 적용 시 건수가 정확히 N이 되고 상태 컬럼이 전부 `공개`
- 상단 상태 값들의 건수 합이 총건수와 일치 (현재는 `자동차` 기준 112건 부족 + 출원/심사중 중복)
- 상단·좌측 같은 값으로 필터 시 건수 동일 (`등록` 725 = 725 로 이미 성립)

- 연산자 단독·후행 연산자·연산자 연속·특수문자만 입력에 대한 처리 통일
- 검증 실패한 입력이 히스토리에 누적되지 않도록 처리

**검증 방법**
위 표의 7개 입력에 대해 버튼 상태·문구가 정책과 일치.

## 5. 정책·설계 확정 요청

수정 방향이 갈려 **개발 착수 전에 결정이 필요한 항목**입니다.

### P-01
**검색식 유효성 검증의 차단 정책** (BUG-021 / TC-PAT-FRM-003)

현재 구현은 괄호 짝 오류 시 `검색`을 `disabled`로 **차단**합니다. 설계 원본(`PAT-INP-030`)은 `진단 표시(실행 차단 안 함)`로 규정되어 있어 서로 다릅니다.

구현 우선 원칙에 따라 **차단 정책을 정답으로 보고 설계 문서를 정정**하는 것으로 정리했습니다. 이 방향이 맞는지 확인 부탁드립니다. 확정되어야 [F-10](#f-10)의 나머지 입력 유형 처리를 정할 수 있습니다.

### P-02
**논문 `초기화` 후 `pageSize`·`sort` 잔존** (D43 / TC-PAP-INP-006)

`?query=도서관&sort=PUBLICATION_DATE_DESC&pageSize=100&pageNo=3` 상태에서 `초기화` → `?lang=ko&sort=PUBLICATION_DATE_DESC&pageSize=100`

`query`·`pageNo`는 제거되고 `pageSize`·`sort`는 남습니다. 검색식 비움·버튼 `disabled`·라디오 기본값 복귀·빈 상태 E2는 모두 정상입니다.

`pageSize`·`sort`는 입력값이 아니라 **표시 옵션**이므로 유지가 의도일 수 있습니다. 초기화 범위를 확정해 주세요.

### P-03
**목록에서 상세로 가는 상호작용 (특허 vs 논문)** (BUG-026 · N-08 · N-09 / TC-PAP-LST-003 · TC-PAT-LST-008·011)

현재 세 화면의 동작이 서로 다릅니다.

| 화면 | 제목 클릭 | 문헌번호 클릭 |
|---|---|---|
| 특허 목록 | 링크 아님 (동작 없음) | **새 탭** 열림 (`target="_blank" rel="opener"`) |
| 논문 목록 | 미리보기 오버레이 개방, URL 불변 | — |

- 논문의 오버레이 개방은 설계 `PAP-LST-021`(선택→패널 오픈)과 **일치**하므로 결함으로 보지 않았습니다
- 특허 문헌번호가 새 탭으로 열리는 것은 2026-08-10에는 **같은 탭 이동**이었으므로 변경된 동작입니다

세 가지를 어떻게 통일할지 결정 부탁드립니다. 결정에 따라 [F-12](#f-12) 처리도 달라집니다.

### P-04
**기간 기본값 정책** ([F-03](#f-03) 1번 관련)

초기 상태의 `최근 5년` 표시를 **쿼리에 적용**할지, **기본값을 `전체`로 바꿔 표시도 맞출지** 결정 부탁드립니다. 현재는 표시와 실제 동작이 다릅니다.
