## BUG-001 `DE 독일`·`GB 영국` 국가 필터가 무시되고 KR 문헌 반환

- **심각도** 치명
- **화면** `특허 검색` — `국가` 필터
- **사전조건** 검색식 `자동차`, `문헌종류`=`전체`, `기간`=`전체`, `상태`=`전체`
- **재현 절차**
  1. `국가` `전체` 클릭 후 `DE 독일` 만 선택
  2. `검색` 클릭
  3. 결과 건수와 상위 행 확인
  4. `GB 영국` 으로 바꿔 반복
  5. `KR 한국` 단독 결과와 비교
- **기대** 선택 국가의 문헌만 반환 (`PAT-INP-011` postcondition `countries[] 포함`)
- **실제**
  - `DE 독일` → URL `countries=DE`, `158,490건`
  - `GB 영국` → URL `countries=GB`, `158,490건`
  - 두 결과의 상위 4행이 `KR 한국` 단독 결과와 **완전히 동일**
    `취하 1019830008862 A 자동차용안전표시기 치우난무 1982-02-04`
    `거절 1019870003303 A 자동차가솔린엔진전자기동장치 주식회사선우상공 1985-09-23`
    `취하 1019870003903 A 자동차의자전장치 김영식 1985-10-28`
    `거절 1019870004851 A 자동차외장보호장치 이규수 1985-11-28`
  - 문헌번호가 `10198…` (KR 출원번호 형식), 출원인이 한국 기업·개인
- **대조** `JP 일본`·`CN 중국`·`EP 유럽`·`PCT` 는 모두 `0건` 으로 정상 필터링
- **영향** 사용자가 독일·영국 특허를 조회했다고 오인한다. 선행기술조사 결과의 신뢰성이 훼손된다

## BUG-002 `분류코드 검색 대상`=`Current Only` 선택 시 검색 실패

- **심각도** 치명
- **화면** `특허 검색` — `항목별 상세검색` / `분류코드`
- **재현 절차**
  1. `항목별 상세검색` 펼침
  2. `IPCM` `IPC (Main)` 필드에 `G06F*` 입력
  3. `분류코드 검색 대상` 을 `Current Only` 로 변경
  4. `검색` 클릭
- **기대** `IPCM` 필드 검색이 현재 분류 기준으로 실행
- **실제**
  - 조립된 검색식 `IPCM:(G06F*) AND IPCCM:(G06F*)` — `IPCCM:` 절이 **추가 누적**됨
  - 오류 안내 `검색에 실패했습니다.\n새로고침 후(F5) 다시 시도해 주세요.`
  - 결과 영역에 건수·목록이 렌더되지 않음
- **대조** `Original or Current`(기본) → `IPCM:(G06F*)` → `1,253,662건` 정상
- **참고** `IPCCM` 은 `검색 필드 추가` 카탈로그(82개)에 존재하지 않는 코드
- **영향** 해당 옵션 조합에서 분류코드 검색을 쓸 수 없다

## BUG-003 `기간` 기본 선택 `최근 5년` 이 실제 쿼리에 미적용

- **심각도** 중대
- **화면** `특허 검색` — `기간` 필터
- **재현 절차**
  1. `초기화` 클릭 → `기간` 이 `최근 5년` `checked` 로 표시됨을 확인
  2. 검색식 `자동차` 입력 후 `검색` → URL·건수 확인
  3. `기간` `최근 5년` 을 명시적으로 클릭한 뒤 `검색` → URL·건수 확인
- **기대** 표시된 선택값이 그대로 쿼리에 반영 (`PAT-INP-013` postcondition `dateFrom/dateTo 반영`)
- **실제**
  - 기본 상태: URL `?lang=ko&query=자동차` — **날짜 파라미터 없음**, `158,490건` (= `전체` 와 동일)
  - 명시 클릭 후: URL `dateFrom=2021-08-10&dateTo=2026-08-10`, **`0건`**
- **영향** 화면이 `최근 5년` 으로 좁혀졌다고 표시하는데 실제로는 전체 기간을 검색한다. 사용자가 결과 범위를 오판한다

## BUG-004 `상태` `출원` 과 `심사중` 의 결과가 완전히 동일

- **심각도** 중대
- **화면** `특허 검색` — `상태` 필터 (`상태 A` 그룹)
- **사전조건** 검색식 `자동차`, `기간`=`전체`, `국가`=`전체`
- **재현 절차**
  1. `상태` `전체` → `출원` 선택 → `검색`. 건수·상위 5행 기록
  2. `상태` `전체` → `심사중` 선택 → `검색`. 건수·상위 5행 기록
  3. 두 결과 비교
- **기대** 서로 다른 상태이므로 다른 결과 집합
- **실제** 건수 모두 `4,205건`, 상위 5행이 완전히 동일
  `1020130131602 A` `1020140025674 A` `1020140049871 A` `1020140062534 A` `1020140144618 A`
- **영향** 두 상태를 구분해 조회할 수 없다

## BUG-005 역전 일자 범위가 안내 없이 무시되고 입력값만 남음

- **심각도** 중대
- **화면** `특허 검색` — `시작일` / `종료일`
- **재현 절차**
  1. `시작일` `2010-01-01`, `종료일` `2010-12-31` 입력 → `검색` → `2,628건` 확인
  2. `시작일` `2020-12-31`, `종료일` `2020-01-01` (역전) 입력
  3. 안내 문구·`검색` 버튼 상태 확인 후 `검색` 클릭
- **기대** 역전 범위에 대한 안내 또는 차단
- **실제**
  - 안내 문구 없음, `검색` 버튼 활성
  - 제출해도 URL·건수가 이전 조건(`dateFrom=2010-01-01&dateTo=2010-12-31`, `2,628건`) 그대로
  - 입력창에는 역전 값(`2020-12-31` / `2020-01-01`)이 남음
- **영향** 화면 표시와 실제 적용 조건이 어긋난 채로 남아, 사용자가 새 기간이 적용됐다고 오인한다
- **미확인** 컴포넌트가 값을 거부한 것인지 제출 시 무시된 것인지는 판별하지 않음

## BUG-006 `TAC_DSC` 코드가 저장되지만 파싱되지 않아 재검색이 재현 실패

- **심각도** 중대
- **화면** `특허 검색` — `검색 히스토리`
- **재현 절차**
  1. `검색어 범위` 를 `상세설명` 으로 선택하고 검색식 `자동차` 로 `검색` → `401,480건` 확인
  2. `검색 히스토리` 펼침 → 항목이 `TAC_DSC:(자동차)` 로 저장된 것 확인
  3. 해당 항목의 `재검색` 클릭
- **기대** 원래 결과(`401,480건`) 재현
- **실제** URL `query=TAC_DSC:(자동차)&scope=DESCRIPTION&countries=US,KR&datePreset=ALL` → **`0건`**
- **직접 입력 대조**
  - `TAC_DSC:(자동차)` 타이핑 → 검증 통과, `0건`
  - `KEY:(자동차)` 타이핑 → `158,490건` 정상
- **대조** `KEY:(자동차)` 항목의 `재검색` 은 저장 당시 조건(`dateFrom=2010-01-01`)까지 복원해 `2,628건` 을 정확히 재현. 즉 재검색 자체는 충실하며 문제는 `TAC_DSC` 코드
- **영향** `상세설명` 범위로 한 모든 검색 이력이 재검색으로 재현되지 않는다. 유효성 검증도 이를 잡지 못한다

## BUG-007 Enter 키 제출 미구현

- **심각도** 중대
- **화면** `특허 검색` — `검색식`
- **재현 절차** 검색식에 `도서관` 입력 후 입력창에 포커스를 두고 Enter 키 입력
- **기대** 설계 `PAT-INP-041` interaction `클릭 / ⏎` → 검색 실행
- **실제** URL 변화 없음, 검색 미실행. 입력창에 개행만 추가됨
- **검증** 스크립트 KeyboardEvent 와 실제 키 입력 양쪽 모두 미제출 → 테스트 방법 오류 아님

- **기대** 설계 `PAT-INP-062` — `★즐겨찾기` 별 아이콘 토글, `즐겨찾기 on/off 저장`

- **실제** `scrollTop` 0 → `9,921` 로 이동하나 `기타정보` 섹션은 여전히 3,785px 아래. 6초간 5회 재측정에도 `9,921` 고정(스무스 스크롤 아님). 최대 스크롤은 `12,974` 이므로 더 이동할 여지가 있음
- **테스트 주의** 스크롤 컨테이너는 window 가 아니라 내부 `div.flex.flex-1.flex-col.overflow-auto` 다. `window.scrollY` 로 판정하면 항상 0이라 오탐이 난다

## BUG-030 특허 상세 섹션 탭으로 위로 되돌아가지 못함

- **심각도** 중대
- **재현 절차** `scrollTop` 이 `9,921` 인 상태에서 `서지사항` 탭 클릭
- **기대** 문서 상단의 `서지사항` 섹션으로 이동
- **실제** `scrollTop` 이 `9,921` 에서 전혀 움직이지 않음. `서지사항` 섹션은 9,556px 위에 있어 화면에 없음. 활성 탭 표시만 `서지사항` 으로 변경
- **영향** 상세 문서를 아래로 내려간 뒤 앞 섹션으로 되돌아갈 수 없다

## BUG-031 활성 탭 표시가 클릭한 탭과 어긋남

- **심각도** 경미
- **실제** `기타정보` 클릭 후 활성 탭(`aria-selected="true"`)이 `상세설명` 으로 표시됨

## BUG-032 로드 완료 전 탭 클릭이 무시되며 피드백이 없음

## 결함 아님으로 확정한 항목

재조사를 방지하기 위해 기록한다.

### URL 미인코딩 표기
`@#$%` 검색 직후 `location.href` 가 `?query=@#$%` 로 표시되나, 새로고침 시 `?query=@%23$%25` 로 정규화되고 검색식·결과가 정상 복원됨 → 기능 손실 없음

### 스크립트 클릭으로 드롭다운 미개방
스크립트 `element.click()` 은 `pointerdown` 을 발생시키지 않아 Radix 계열 트리거(`언어 설정`, `국가설정`, `정렬`, `페이지당 개수`)가 반응하지 않음. 실제 입력 이벤트로는 정상 → 테스트 방법 오류

### 필드절이 범위 라디오를 덮어씀
`DSC:(자동차)` 가 `검색어 범위` 설정과 무관하게 `383,150건` 반환 → 설계 `사용자 직접 필드식은 불변` 과 일치

### 연산자 정합성
`하이브리드`(16,607) − `하이브리드 and 자동차`(1,684) = `하이브리드 not 자동차`(14,923) 정확히 일치. `or`(173,413)은 각 단독어보다 큼. 대소문자 무관(`AND`=`and`)

### 문헌종류 필터 정합성
`공개`(73,464) + `등록`(17,481) + `실용공개`(67,184) + `실용등록`(361) = `전체`(158,490) 정확히 일치

### 국가 필터 정합성 (KR·US 한정)
`KR`(158,490) + `US`(0) = 기본 `KR·US`(158,490) 정확히 일치. `PCT` 라벨 → URL 값 `WO` 매핑도 정상

### 범위코드 단조 확장
`KEY`(158,490) < `TAC`(168,578) < `TAC_DSC`(401,480). 라디오 `명칭+요약+독립항`·`명칭+요약+전체청구항` 은 각각 `KEY:()`·`TAC:()` 필드절과 건수가 정확히 일치

### 항목별 상세검색 조립
`TI`=`도서관`, `AB`=`"전기 자동차"` → `TI:(도서관) AND AB:("전기 자동차")` 조립. 실행 후 입력값만 비우고 필드 구성 유지 → 설계 `PAT-INP-050` 과 일치

### `초기화`
URL·검색식·필터·결과가 모두 초기 상태로 복귀. 언어 설정만 유지 → 설계 `PAT-INP-042` 와 일치

### `국가설정` 대화상자
`선택 추가` 시 선택 국가가 국가 그룹에 선택 상태로 추가되고, `취소` 시 변경이 반영되지 않음 → 정상

### `정렬`·`페이지당 개수`
`매칭순`/`출원일(최신)`/`출원일(오래된)` 정렬 방향 정상(`sort=APPLICATION_DATE_DESC`/`ASC`). `페이지당 개수` 선택값과 실제 행수 일치(`50개` → 50행)

### 페이지네이션
`2` → `pageNo=2`, `다음 페이지 그룹` → `pageNo=11`(버튼 11~20), `이전 페이지 그룹` → `pageNo=10`(버튼 1~10). 1페이지에서 `이전 페이지 그룹` 은 `disabled`

### 좌측 `권리상태` 패싯 집계 정합
`등록`(725) + `소멸`(344) + `거절`(308) + `공개`(180) + `취하`(113) + `포기`(14) = `1,684건` 전체와 정확히 일치.

`독립항`(기본, 4,366자) ↔ `전체청구항`(7,786자) 전환 및 원복 정상
