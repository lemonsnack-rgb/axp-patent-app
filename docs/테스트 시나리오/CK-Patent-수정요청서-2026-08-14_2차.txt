CK Patent_[오류] 검색 필드 27종 선택 시 검색 실패(502)
          대상 : 특허 검색 – 항목별 상세검색 – [+ 검색 필드 추가·확장]
          이력 : 1차 오류 1 · 기존 F-02 · 2026-08-12 최초 지적 후 미수정 지속
                 2차 점검에서 전 필드 전수 조사, 동일 원인 27종으로 범위 확정
          캡처 : 오류01_검색필드-27종-502-전수결과.png
          연계 : 분류코드 Current Only 는 기능 정의 미확정으로 본 항목에서 분리
                 → §7 검토 후 구현 1) 참조

▸ 수정 사항 요약
   - 화면에서 선택 가능한 검색 필드 82종 중 27종이 서버 502 로 검색 실패
   - UCM · UC · FI · FTC 등 카탈로그에 노출된 필드가 포함됨
   - 고를 수 있는 필드의 약 1/3 이 검색 불가 상태
   - 세 차례 순회에서 동일 재현. 착수되지 않음

▸ 기대 결과
   - 화면에서 선택 가능한 모든 검색 필드는 502 없이 결과를 반환해야 함
   - 필드를 없애거나 감추는 방식은 대안으로 인정하지 않음 (기획 확정)

▸ 재현 방식
   1. 특허 검색 진입 → [초기화] → [항목별 상세검색] 펼침
   2. [+ 검색 필드 추가·확장] 열기
   3. UCM 선택 후 값 707 입력하고 [검색] → 502
   4. UC · FI · FTC 로 3번 반복 (FI 는 G06F* / FTC 는 5B075*)
   5. 아래 502 27종 목록의 나머지 필드도 동일하게 단독 검색
   ※ 관찰 지점 : Network 탭 응답 코드 · 화면 안내 문구

▸ 현재 상태  (qc.9 실측)

   (1) 검색 필드 전수 점검 — 82종 중 27종이 502
   - 정상 200 (53종)
       TI AB CL CLI CLA KC KWD DSC TF BT IE SM SP DE DD AN PN RN FN PRN
       IPN IAN DC AP APC APD INV AG AGD EXN IPCM IPC CPCM CPC CAP ASNO
       ASNE EL PLGE NRTBT NRTDO NRTN SEI SET SEQC AD PD RD FD PRD IPD IAD SED
   - HTTP 502 (27종)
       WAP INVC AC PCN UCM UC FI FTC CAC ASY LY JIC BCC BCN FCC FCN
       NPCY SEYN SESO SEN SEDC SEDD SEQY CAD LRD NRDS NRDE
   - 기타 : PRC → HTTP 504 / NPRD → HTTP 400
   - 응답 : {"code":"HTTP_CLIENT_ERROR","message":"외부 시스템 연동 중 오류가 발생했습니다."}
   - 화면 : "검색에 실패했습니다. 새로고침 후(F5) 다시 시도해 주세요."

   (2) 실패 지점 절단 — 필드 코드는 서버에 등록되어 있음
   - 미등록 코드(ICM · IC · IPCR · IPCX · ZZZZ) → HTTP 400
     "지원하지 않는 검색 필드 코드입니다."
   - 위 27종 → HTTP 400 이 아니라 HTTP 502
   - 즉 서버는 해당 코드를 유효 코드로 인식하며, 실패는 그 다음 연동 구간에서 발생
   - 프론트가 잘못된 코드를 만들어 보내는 문제가 아님
     ※ 1차·2차 요청서에 기재했던 "카탈로그 미등재 코드로 조립되어 502" 는
       위 400/502 구분 실측으로 정정합니다

   (3) 대조군 — 같은 그룹의 정상 필드
   - IPCM:(G06F*)   200 · 134,975건      / IPC:(G06F*)   200 · 204,738건
   - CPCM:(G06F*)   200 · 102,535건      / CPC:(G06F*)   200 · 163,110건
   → 같은 분류코드 그룹 안에서도 IPCM·IPC·CPCM·CPC 는 정상, UCM·UC·FI·FTC 는 502

▸ 상세 수정내역

   ※ 확정 방향 (기획 확정)
      - 화면에서 선택 가능한 필드는 전부 정상 동작해야 함
      - 필드 제거 · 비활성화(disabled) · 비노출 처리는 대안으로 인정하지 않음

   1) 검색 필드 API 연동 완료 — 최우선
      - 위 (1) 의 502 27종 해소
      - PRC(504) · NPRD(400) 도 함께 확인
   2) composition 응답 warnings 활용
      - 현재 실행 불가 필드도 warnings 가 빈 배열이라 클라이언트가 정상으로 보고 실행
      - 실행 불가 필드는 warnings 로 내려 검색 전 차단
      - 단 이는 연동 완료 전 임시 방어이며, 차단 상태를 최종 형태로 두지 않음
   3) 5xx 안내 문구 : "검색에 실패했습니다. 잠시 후 다시 시도해 주세요." + [다시 시도]
   4) 실패 검색 히스토리 미저장 — [개선 1] 에서 함께 처리

▸ 검증 방법
   - 위 (1) 502 27종 각각 단독 검색 시 200 응답
   - 카탈로그에 노출된 필드 전수 재점검에서 502 · 504 가 0종
   - 카탈로그 외 코드는 400 + 명시적 안내로 응답 (502 아님)

 1) 분류코드 [Current Only]  (1차 오류 1 · 기존 F-02 에서 분리)
    - 캡처 : 검토01_분류코드-CurrentOnly-기능정의미확정.png
    - 처리 방침 : 기능 정의 검토를 거친 뒤 구현. 이번 차수 수정 대상 아님
      · 기능 정의가 확정된 적이 없어, 지금 고치면 무엇을 만들지 알 수 없음
      · 옵션 제거 · 비활성화 · 비노출은 대안으로 인정하지 않음 (기획 확정)

    ▸ 현재 상태 (qc.9 실측)
      - IPCM / Original or Current   IPCM:(G06F*)    200 · 134,975건
      - IPCM / Current Only          IPCCM:(G06F*)   HTTP 502
      - IPC  / Current Only          IPCC:(G06F*)    HTTP 502
      - CPCM / Current Only          CPCCM:(C01C*)   HTTP 502
      - CPC  / Current Only          CPCC:(G06F*)    HTTP 502
      - 값과 무관 : IPCCM:(G06F*) · IPCCM:(G06F-017/50) · IPCCM:(B60*) 모두 502
      - 미등록 코드는 400 이나 위 4종은 502 → 서버는 유효 코드로 인식
      - 조립 API 응답 {"query":"IPCCM:(G06F*)","warnings":[]} — 실행 전 차단 없음
      - 셀렉트 옵션값 ORIGINAL_OR_CURRENT / CURRENT

    ▸ 문서·데이터 확인 결과
      - [AXP] 특허검색 동작방식 명세서 전문 검색
          Current 0건 / Original 0건 / IPCCM 0건 / CPCCM 0건
          분류 관련 조항은 [검색-32] "분류 필드(IPC/CPC 등): 분류 코드 입력" 이 전부
        → Original / Current 구분에 대한 기능 정의가 명세에 없음
      - 화면 셀렉트에 툴팁·설명 없음 (title · aria-describedby · 도움말 0건)
      - [BLK] 수집 DB 명세 — 현행 분류 판별 근거 컬럼은 설계에 존재
          KPA_IPC : ipc_version (IPC 버전) · ipc_revision_date (IPC 개정일)
          CPC     : cpc_revision_date (CPC 개정일)
          ipc     : ipc_number · ipc_date (IPC 부여일, KR 만 채움)
        ※ 재분류 전후를 비교하는 별도 이력 스냅샷 테이블은 명세에 없음
        ※ 값이 실제로 채워져 있는지는 미확인
           (상세 API 는 classificationCode.ipc[] = {code} 만 반환, 버전 미노출)
      - [JARVIS-PATENT-API] /search/bigtext 색인 분류 컬럼
          ipc_number_list · cpc_code_list — 버전 · 개정일 구분 없음

    ▸ 검토 시 확정할 사항
      1. 기능 정의 (안)
         "Current Only = 문헌이 보유한 분류코드 중 현행 유효 분류에만
          검색어를 매칭한다. 검색 대상 문헌 범위·기간은 변하지 않으며,
          결과는 Original or Current 의 부분집합이다."
         ※ 날짜 필터가 아님. 최근 문헌만 걸러내는 기능으로 오해되지 않도록 명시
      2. "현행(Current)" 판정 기준 — 적재 데이터로 가능한 안을 개발이 회신
         (a) ipc_version 이 최신인 행
         (b) ipc_revision_date 가 가장 최근인 행
         (c) 현행 IPC 개정판 기준 유효 코드   ← 업계 정의에 가장 가까움
      3. 위 판정에 필요한 컬럼의 실제 적재율

    ▸ 검토 완료 후 검증 방법
      - 셀렉트에 두 값이 모두 있고 둘 다 선택·검색 가능 (비활성·비노출 아님)
      - IPCM · IPC · CPCM · CPC + Current Only 모두 502 없이 결과 반환
      - Current Only 건수 ≤ Original or Current 건수 (IPCM 기준 134,975 이하)
