### F-02 · `분류코드 검색 대상`을 `Current Only`로 바꾸면 검색이 실패함

#### 수정 사항 요약
**미수정.** 2026-08-12과 동일한 원인이며, 서버 응답 코드만 구체화되었습니다.

#### 기대 결과
`Current Only` 선택 시에도 정상 결과 반환. `Original or Current` 대비 건수가 같거나 적어야 합니다(부분집합).

#### 현재 상태

| 필드 | 옵션 | composition 요청 | 조립된 검색식 | 결과 |
|---|---|---|---|---|
| IPCM | `Original or Current` | `{"code":"IPCM","value":"G06F*","scope":"ORIGINAL_OR_CURRENT"}` | `IPCM:(G06F*)` | 정상 (`자동차 AND IPCM:(G06F*)` 364건) |
| **IPCM** | **`Current Only`** | `{"code":"IPCM","value":"G06F*","scope":"CURRENT"}` | **`IPCCM:(G06F*)`** | **HTTP 502** |
| **CPCM** | **`Current Only`** | `{"code":"CPCM","value":"C01C*","scope":"CURRENT"}` | **`CPCCM:(C01C*)`** | **HTTP 502** |

```
POST /api/service/axp/patent-searches → 502
{"code":"HTTP_CLIENT_ERROR","message":"외부 시스템 연동 중 오류가 발생했습니다."}
```
화면 토스트: `검색에 실패했습니다.`

`IPCCM`·`CPCCM`은 `+ 검색 필드 추가·확장` 카탈로그에 존재하지 않는 코드입니다.

#### 상세 수정내역
1. `POST /patent-search-queries/composition`이 `scope=CURRENT`에 대해 생성하는 코드(`IPCCM`/`CPCCM`)를 서버가 실제 지원하는 코드로 교체해 주세요.
2. 지원 코드가 없다면 옵션 자체를 비활성화하거나, 필드절이 아닌 **검색 파라미터**로 전달하도록 변경해 주세요.
3. **502를 `검색에 실패했습니다.` 하나로만 노출하는 것은 부족합니다.**
   - 일시 오류일 때 권장 문구: `검색에 실패했습니다. 잠시 후 다시 시도해 주세요.` + `[다시 시도]`
   - 지원하지 않는 조합이 원인이라면 사전 차단이 맞습니다: `선택하신 분류코드 검색 대상은 현재 지원하지 않습니다.`
4. **502로 실패한 검색이 히스토리에 저장됩니다.** 히스토리에 `IPCCM:(G06F*)`·`CPCCM:(C01C*)`가 남아 `재검색` 시 같은 실패를 반복합니다 → [N-D](#n-d) 참조.

#### 검증 방법
`IPCM`+`Current Only`, `CPCM`+`Current Only` 둘 다 502 없이 결과 반환. 조립된 코드가 필드 카탈로그 안에 있을 것.

#### 현재 상태 (검색식 `자동차`, 국가 기본값 KR)

| 조작 | URL | payload 일자 | 건수 |
|---|---|---|---|
| 초기화 직후 (화면 표시 `최근 5년`) | `?lang=ko&query=자동차` | **없음** | 158,490 |

2. **`최근 5년`만 `datePreset`이 누락** — 다른 프리셋과 직렬화 규칙이 다릅니다
3. **`최근 5년` 결과가 0건** — 검색 인덱스의 최신 출원일이 `2019-07-05`이므로 2021년 이후 적재분이 없습니다

#### 상세 수정내역

### F-04 · 상태 축 — 라벨 중복과 패싯 매핑

#### 수정 사항 요약
**좌측 패싯 `공개` 미적용(N-13)은 수정 확인.** 그러나 **상단 상태 라벨 중복이 2중복 → 3중복으로 악화**되었습니다.

#### 기대 결과
상단·좌측·목록 컬럼이 같은 `register_status` 어휘를 쓰고, 어떤 값으로 필터해도 적용되며, 같은 데이터를 가리키는 라벨이 중복 노출되지 않습니다.

#### 현재 상태 (검색식 `하이브리드 and 자동차`, 기간 전체, 총 1,684건)

**① 수정 확인 — 좌측 패싯 `공개`**

| 조작 | URL | payload | 건수 | 결과표 `상태` |
|---|---|---|---|---|
| 좌측 패싯 `공개 (180건)` → `적용` | `...&fk_statuses=공개` | `{"statuses":["PUBLICATION"]}` | **180** | 전부 `공개` |

패싯 표기 건수와 적용 결과가 일치하고 `statuses`가 정상 전달됩니다. **N-13 해소.**

**② 수정 확인 — 상태별 건수 합계**

| 값 | 건수 |
|---|---|
| 공개 (중복 3라벨 공통) | 180 |
| 등록 | 725 |
| 거절 | 308 |
| 소멸 | 344 |
| 취하 | 113 |
| 포기 | 14 |
| 무효 | 0 |
| **합계** | **1,684 = 총건수** |

2026-08-12의 "112건 부족" 문제는 **해소**되었습니다.

**③ 악화 — 상단 상태 라벨이 3중복**

| 상단 버튼 | payload `statuses` | 건수 | 결과표 `상태` 컬럼 |
|---|---|---|---|
| **출원** | `["APPLIED"]` | **180** | **공개** |
| **공개** | `["PUBLICATION"]` | **180** | **공개** |
| **심사중** | `["UNDER_EXAMINATION"]` | **180** | **공개** |
| 등록 | `["REGISTERED"]` | 725 | 등록 |

서로 다른 3개 코드가 서버에서 같은 집합으로 수렴합니다. 2026-08-12에는 `출원`·`심사중` 2중복이었고, 이번에 `공개`가 **추가**되면서 3중복이 되었습니다. 좌측 패싯에는 `공개` 하나만 존재합니다.

#### 상세 수정내역
1. **[필수] 상단 `출원`·`심사중`을 제거하고 `공개` 하나만 남겨 주세요.** 실측상 세 코드가 동일 집합이므로 UI에 셋으로 노출할 근거가 없습니다. 서버에서 정말 구분되어야 한다면 `APPLIED`·`UNDER_EXAMINATION`이 각각 별도 집합을 반환하도록 수정해 주세요.
2. **[권고] 축 이름 정리** — 값 집합이 `등록·공개·거절·소멸·취하·포기·무효` 7종이므로 아래를 제안합니다.

| 대상 | 현재 | 권고 |
|---|---|---|
| 상단 필터 | `상태` (출원·공개·심사중 3중복) | `등록상태`, 값 7종 |
| 좌측 패싯 | `권리상태` | `등록상태` — 공개 단계에는 권리가 없으므로 "권리"는 부정확 |
| 목록 컬럼 헤더 | `상태` | `등록상태` |
| 상단 A/I 그룹 | A: 출원·공개·심사중·등록 | A: **공개**·등록 / I: 거절·소멸·취하·포기·무효 |

3. `문헌종류` 라벨은 `공개특허공보`/`등록특허공보`로 **정상 반영 확인**했습니다. 다만 영문 전환 시 `Published`/`Registered`로 축약되어 상태 축과 단어가 다시 충돌합니다 → [N-E](#n-e) 참조.

#### 검증 방법
상단 상태 값 목록에 동일 집합을 가리키는 라벨이 1개만 존재할 것. 상단·좌측 같은 값 필터 시 건수 동일(`등록` 725 = 725로 이미 성립).

### F-07 · 일자 필드코드는 표기 1종만 동작하며 화면에 안내가 없음

#### 수정 사항 요약
**미수정.** 이번에 **PD·RD 미측정분을 완료**했고 **동작하는 표기 1종을 특정**했습니다. 2026-08-12의 "일자 필드 검색이 불가능하다"는 서술은 **정정이 필요합니다** — 특정 표기로는 동작합니다.

#### 기대 결과
기능정의서 표기 `CODE:([from ~ to])`로 일자 필드절 검색이 실행됩니다.

#### 현재 상태 — 검색식 직접 입력

| 입력 | 버튼 | 결과 |
|---|---|---|
| `AD:([2020-01-01 ~ 2020-12-31])` (기능정의서 표기) | **disabled** | V1 `검색식 형식이 올바르지 않습니다. 괄호·연산자(AND·OR·NOT)·따옴표 짝을 확인해주세요.` |
| `AD:([20100101~20101231])` (대괄호만 추가) | **disabled** | 동일 V1 |
| `AD:(2020-01-01 ~ 2020-12-31)` (하이픈·공백) | 활성 | **502** → 토스트 `검색에 실패했습니다.` |
| **`AD:(20100101~20101231)`** | 활성 | **정상 172,072건** |

`PD`·`RD`도 **완전히 동일**합니다 (대괄호 → disabled+V1 / 하이픈 표기 → 502 / `YYYYMMDD~YYYYMMDD` → 정상).

#### 현재 상태 — `항목별 상세검색` 위젯 경로 (2026-08-12 미검증분)

| 필드 | 조립된 검색식 | 결과 |
|---|---|---|
| AD 출원일 `2020-01-01`~`2020-12-31` | `AD:(20200101~20201231)` | 200 · 0건 |
| PD 공개일/특허일 동일 | `PD:(20200101~20201231)` | 200 · 0건 |
| RD 등록일 동일 | `RD:(20200101~20201231)` | 200 · 0건 |

**위젯 경로는 정상 동작합니다.** 0건인 것은 검색 인덱스의 최신 출원일이 2019-07이기 때문이며, 적재 범위 안(2010년)으로 바꾸면 172,072건이 반환됩니다.

#### 상세 수정내역
1. **지원 표기가 `CODE:(YYYYMMDD~YYYYMMDD)` 하나뿐인데 화면 어디에도 안내가 없습니다.** 검색식 placeholder는 `예: 하이브리드 and 자동차 | *수소 자동차*`로 일자 문법을 다루지 않습니다.
   - 최소 조치: placeholder 또는 도움말에 `예: AD:(20200101~20201231)` 명시
2. **하이픈 포함 ISO 표기(`2020-01-01`)가 클라이언트 검증을 통과한 뒤 서버에서 502로 죽습니다.** 사용자가 가장 자연스럽게 입력하는 형태이므로 클라이언트에서 자동 정규화하거나 검증 단계에서 차단해 주세요.
   - 차단 시 권장 문구: `일자는 YYYYMMDD 형식으로 입력해 주세요. (예: AD:(20200101~20201231))`
3. **기능정의서의 `[from ~ to]` 대괄호 표기를 지원할지 결정해 주세요.** 지원하지 않는다면 문서 정정 대상입니다.
4. V1 문구가 실제 원인과 어긋납니다 — 대괄호가 원인인데 `괄호·연산자·따옴표 짝을 확인해주세요`가 표시됩니다.

#### 검증 방법
안내된 표기로 입력 시 V1·502 없이 실행되고, 결과 출원일이 해당 구간 안에 있을 것.

### F-11 · 국가 필터의 URL 직렬화가 반대로 되어 있음

#### 수정 사항 요약
**미수정.** 원래 지적한 `countries=` 빈 값이 그대로이고, **선택한 국가가 URL에 실리지 않는 문제가 추가로 확인**되었습니다.

#### 기대 결과
기본/전체 상태에서는 파라미터를 생략하고, 특정 국가를 선택하면 URL에 반영됩니다(공유·새로고침 시 조건 유지).

#### 현재 상태 (검색식 `자동차`, 기간 전체)

| 국가 선택 | URL | 요청 payload | 건수 |
|---|---|---|---|
| `전체` | `...&datePreset=ALL&countries=` (**빈 값 잔존**) | `countries` 키 **없음** | 158,490 |
| `KR 한국` | `...&datePreset=ALL` (**countries 없음**) | `"countries":["KR"]` | 158,490 |

**직렬화가 반대입니다.** 값이 있는 쪽(KR)은 URL에서 사라지고, 값이 없는 쪽(전체)은 빈 키가 남습니다.

`전체`만 `pressed`가 되고 재클릭해도 해제되지 않는 라디오 성격은 **정상 동작**입니다.

#### 상세 수정내역
1. 빈 배열일 때 쿼리스트링에서 `countries` 키 자체를 제거해 주세요.
2. **선택된 국가는 URL에 실어 주세요.** 현재 상태를 URL로 공유하거나 새로고침하면 조건이 유실됩니다(기본값이 KR이라 우연히 같은 결과가 나올 뿐입니다).
3. `전체`와 `KR`이 같은 158,490건을 반환합니다. 적재가 KR뿐이라 값이 같은 것인지, `전체`가 실제로 KR로만 조회되는 것인지 확인 부탁드립니다.

#### 검증 방법
`전체` 선택 후 URL에 `countries` 키가 없을 것. `KR` 선택 후 URL에 `countries=KR`이 있고, 그 URL을 새 탭에서 열면 KR이 선택된 상태로 복원될 것.

### F-17 · 서지 `도면 수`가 `0건`인데 `도면 (1)` 섹션이 존재

#### 수정 사항 요약
**미수정.** 개별 사례가 아니라 **표본 30건 중 27건(90%)에서 발생하는 구조적 불일치**입니다.

#### 기대 결과

#### 현재 상태

QC 데이터 30건 표본 조회 결과:

| 항목 | 건수 |
|---|---|
| 검사 문헌 | 30 |

- 서지사항 `도면 수` = **`0건`**
- 하단 `도면 (1)` 섹션에 `대표 / 도 1 / 도면 설명 / 확대 / **도면 이미지 없음**` 표시

```json
"bibliographic": { "drawingCount": 0 },
"figures": [ { "image": null, "description": "도 1은 본 발명의 …" } ]
```

`figures`에 담긴 것은 **도면 이미지가 아니라 `도면의 설명` 텍스트 한 덩어리**입니다. 실제 도면 이미지는 27건 전부 없습니다.

#### 상세 수정내역
1. **`figures` 배열의 정의를 확정해 주세요.** 현재는 이미지 없이 `도면의 설명` 텍스트만 들어 있어, 이것을 "도면 1건"으로 세는 것이 맞는지 불분명합니다.
   - `drawingCount`가 정답이라면 → 이미지가 없는 `figures` 항목은 `도면` 섹션에서 제외하고, 설명 텍스트는 `상세설명 > 도면의 설명`에만 노출
   - `figures`가 정답이라면 → `drawingCount`를 배열 길이로 재계산
2. **도면 이미지 적재 여부를 확인해 주세요.** 표본 27건 전부 `image: null`이므로 도면 이미지가 아예 적재되지 않은 것으로 보입니다. 적재 예정이라면 `도면 이미지 없음` 대신 준비 중 상태를 명시해 주세요.
   - 권장 문구: `도면 이미지는 준비 중입니다.` (현재 `도면 이미지 없음`은 원본에 도면이 없다는 의미로 읽힙니다)
3. `확대` 버튼이 이미지 없이도 노출됩니다. 이미지가 없을 때는 비활성 처리해 주세요.

#### 검증 방법
서지 `도면 수`와 `도면 (N)` 섹션의 N이 일치할 것. 표본 30건 재측정 시 불일치 0건.

#### 현재 상태

| 항목 | 2026-08-12 | 2026-08-14 |
|---|---|---|
| 화면 내 URL 평문 표시 | 노출 | **`<button>`으로 변경 — 해소** |

2. 가능하면 서비스 도메인 경유 프록시 또는 서명 URL로 대체해 주세요.

#### 검증 방법

|---|---|

## 7. 신규 확인 사항

### N-B · 검색어 범위의 URL 파라미터 값이 payload와 다르고, 삭제된 라벨을 사용

| 화면 라벨 | URL `scope` | payload `searchScope` |
|---|---|---|
| 명칭+요약+독립항 (기본) | (생략) | `NAME_ABSTRACT_INDEPENDENT_CLAIM` |
| 명칭+요약+전체청구항 | `TITLE_ABSTRACT_ALL_CLAIMS` | `NAME_ABSTRACT_ALL_CLAIMS` |
| **전체 필드** | **`DESCRIPTION`** | `NAME_ABSTRACT_ALL_CLAIMS_DETAIL` |

URL과 payload가 서로 다른 어휘를 씁니다(`TITLE_` vs `NAME_`). 특히 `전체 필드`의 URL 값 `DESCRIPTION`은 이번에 삭제된 `상세설명` 라벨의 잔재로 보입니다. 세 어휘를 하나로 통일해 주세요.

### N-C · 검색어 범위 `상세설명`이 삭제되었습니다
2026-08-11 순회 대상이던 4번째 옵션 `상세설명`이 사라지고 3종이 되었습니다. 의도된 변경인지 회신 부탁드립니다. `항목별 상세검색`의 `DSC 상세설명` 필드는 그대로 존재합니다.

### N-D · 실패한 검색도 히스토리에 저장됨
- 502로 실패한 `IPCCM:(G06F*)` · `CPCCM:(C01C*)`
- 하이픈 표기로 502가 난 `AD:(2020-01-01 ~ 2020-12-31)` · `PD:(…)` · `RD:(…)`
- 0건으로 끝난 `KEY:(and)` · `KEY:(or)` · `KEY:(not)` · `KEY:(@#$%)`

모두 히스토리에 남아 `재검색` 시 같은 실패를 반복합니다. **실패한 검색은 저장하지 않는 것을 제안합니다.**

### N-E · 영문 전환 시 문헌종류·상태 라벨이 다시 충돌
