## A. 특허 도메인 용어

특허 명세서라는 결과물 자체를 구성하는 개념. 실무 표준 용어이므로 임의 변형 없이 그대로 쓴다.

| # | 용어 | 대응(영문/코드) | 정의 | 관련 | 금지/유의 |
|---|---|---|---|---|---|
| A-01 | 직무발명서 | IDF (invention disclosure form) | 발명자가 발명 내용을 회사에 신고하는 문서. **본 서비스의 유일한 입력물** — 이용자가 PDF 1개를 올리면 AI가 여기서 발명 설명·이미지를 추출해 모든 후속 단계의 재료로 쓴다. API 경로의 `idf`가 이것 | 발명 설명, 도면 | 직발서(내부 축약 — 화면 노출 금지) |
| A-02 | 명세서 | `InventionSpecification` | 특허 출원 시 제출하는 발명의 기술 문서. 국내 표준 섹션(기술분야 → 배경기술 → 해결과제 → 해결수단 → 효과 → 도면의 간단한 설명 → 부호의 설명 → 실시예 → 청구범위 → 요약)으로 구성. **본 서비스의 최종 산출물**이며 에디터에서 편집해 DOCX·PDF로 내보낸다 | 중간명세서, 에디터, 섹션 | — |
| A-03 | 중간명세서 | (서비스 조어 · `MidspecSection[]`) | 실시예(가장 오래 걸리는 생성)를 **제외한** 명세서 초안. 8단계 확정 내용으로 먼저 생성해 이용자가 검토·수정하는 중간 산출물이다. 여기서 「명세서 생성」을 누르면 실시예가 더해져 완성 초안이 되고 에디터로 넘어간다 | 명세서, 실시예, 명세서 생성 | — |
| A-04 | 실시예 | embodiment (`embodiment_description`) | 발명을 실제로 구현하는 구체적 방법을 도면·부호를 인용해 서술한 섹션(국내 명세서의 "발명을 실시하기 위한 구체적인 내용"). 생성에 1분 이상 걸려 **별도 로딩 오버레이**로 처리한다 | 중간명세서, 명세서 생성 | — |
| A-05 | 발명 설명 | `InventionDescriptionItem` | 직무발명서에서 추출한 발명 서술 조각(항목)들. 각 항목은 라벨(배경기술·목적·구성(해결수단)·효과·기타)과 유형(텍스트/표)을 가지며, **제안기술/종래기술 두 그룹**으로 나뉜다. 여기서 채택한 항목이 구성요소·청구항·명세서 생성의 근거가 된다 | 제안기술, 종래기술, 항목, 채택 | — |
| A-06 | 제안기술 / 종래기술 | `proposed` / `previous` (라벨: `proposed_implementation` / `previous_implementation`) | 제안기술 = 이 발명이 새로 제안하는 내용, 종래기술 = 기존에 존재하던 기술(발명의 배경·비교 대상). 발명 설명 항목과 도면 분류에 공통으로 쓰는 2대 구분이며, 화면에서는 좌우 2열(발명 설명)과 분류 배지(도면)로 표시된다. 항목은 두 그룹 사이로 끌어 옮길 수 있다 | 발명 설명, 분류 | 선행기술(검색 모듈 용어 — 여기서 혼용 금지) |
| A-07 | 구성요소 | `InventionElement` | 발명을 이루는 기술 단위(예: 데이터 수집부, 전처리부). 명칭(국/영)·상위어(국/영)·정의·부호를 가진다. **청구항 생성의 기준이자 문서 전체 명칭의 원천** — 명칭을 바꾸면 발명 설명·청구항·중간명세서·에디터 본문의 모든 언급이 함께 치환된다(부호 보존·긴 이름 우선 매칭) | 부호, 하이라이트, 이름 전체 변경 | 구성 요소(띄어쓰기 금지) |
| A-08 | 부호 | reference sign (`InventionElement.symbol`) | 도면과 본문에서 구성요소를 가리키는 번호. 「부호 자동 부여」가 순서·계층 기준으로 부여한다: 최상위 100·200…, 하위 110·120…, 그 하위 111…. 채택 항목에만 부여되고, 미부여는 `—`로 표시. 에디터 「부호의 설명」 섹션이 `100: 명칭` 줄로 자동 조립된다 | 구성요소, 부호의 설명 | 도면부호·참조부호(혼용 금지 — "부호"로 통일) |
| A-09 | 도면 | `Drawing` (image: `ImageFile`+`BBox`, detail: symbol/name/description/label) | 명세서에 들어가는 그림. 직무발명서 페이지에서 추출되며, 원본 페이지 이미지 안의 위치(BBox)를 갖는다. ③ 이미지 선별에서 "이미지"로 불리다가 ⑥에서 채택되면 "도 N"이 된다 | 도 N, BBox, CAD 변환 | 그림·이미지(⑥단계 이후 혼용 금지) |
| A-10 | 대표도 / 대표도면 | `isRepresentative` (클라이언트 상태) | 발명을 대표하는 그림 1개. ③단계에서는 "대표 이미지"(이후 AI 생성의 기준), ⑥단계에서는 "대표도면"(요약서에 `【대표도】 도 N`으로 기재, 청구항 생성 시 대표도 우선 전달 — API는 최대 3개 허용, 현재 1개 지정). **이용자가 직접 지정**하며 자동 지정은 확정 시 비어 있을 때만 | 도면, 요약 | — |
| A-11 | 청구항 | claim (`ClaimItem`) | 특허로 보호받으려는 권리 범위를 정의하는 문장. 번호는 목록 위치로 자동 부여되고, 순서 변경·삭제 시 본문의 `제N항` 인용도 자동 갱신된다 | 독립항, 종속항, 청구범위 | — |
| A-12 | 독립항 | independent claim | 다른 항을 인용하지 않고 발명을 완결적으로 정의하는 청구항. 화면에서는 인용 문구(`제N항`)가 없으면 독립항으로 판정해 파란 배지를 붙인다 | 독립항 세트, 종속항 | — |
| A-13 | 종속항 | dependent claim (`depends_on`) | 앞 항을 인용해(`제N항에 있어서, …`) 범위를 한정·구체화하는 청구항. 인용 대상은 단일 항만 지원(다중 인용은 이번 버전 제외). 자기/후행 항 인용은 `⚠ 번호 확인` 오류 배지 | 독립항, 연관 구성요소, 종속항 분량 | — |
| A-14 | 독립항 세트 | `ClaimSet` (`independent-claim/set`) | "독립항 2~3개(장치항+방법항 등) 묶음"인 AI 추천 후보. 권리범위 설정에 맞춰 최대 5개(넓은 2·균형 2·한정 1)가 생성되고 **이용자는 1개만 선택**한다. 선택한 세트의 독립항마다 종속항 그룹이 생긴다 | 권리범위, 추상화 수준, 청구항 구성 | — |
| A-15 | 권리범위 | (서비스 표기) | 청구항이 보호하는 범위의 넓이. ⑦단계 1구역 「권리범위 설정」에서 추상화 수준+청구항 구성으로 정하며, 세트 카드 제목에 `넓은/균형/한정 권리범위`로 표기된다 | 추상화 수준, 독립항 세트 | — |
| A-16 | 추상화 수준 | `abstraction_level` = BROAD/INTERMEDIATE/NARROW | 청구항을 얼마나 넓게 쓸지의 단계. 화면 표기 **넓은**(보호 범위 최대·등록 난이도↑) / **균형**(기본값) / **한정**(구체 한정·등록 용이). 바꾸면 세트를 다시 생성해야 한다 | 권리범위 | 상·중·하 등 임의 표기 금지 |
| A-17 | 청구항 구성 | `Preference.claims[].category` = MACHINE/PROCESS/MANUFACTURE/COMPOSITION | 세트를 어떤 종류의 항으로 짤지(2~3개 슬롯). 화면 표기 **장치항**(구성요소의 결합) / **방법항**(단계·동작, SW 발명에 유리) / **제조항**(제조 방법으로 얻은 물건) / **조성물항**(성분·배합). 슬롯마다 방향·강조점 설명을 붙일 수 있다 | 독립항 세트 | 카테고리(화면 노출 금지) |
| A-18 | 종속항 분량 | `claim_count_level` = LOW/MEDIUM/HIGH | 전체 청구항 개수 목표. 화면 표기 **적게**(10~14항) / **보통**(13~17항) / **많이**(16~20항). 바꾸면 종속항이 다시 생성된다(편집 소실 — 확인 다이얼로그) | 종속항 | — |
| A-19 | 청구범위 | claims (에디터 섹션) | 명세서 문서 안에서 청구항들이 놓이는 섹션의 정식 명칭. **위저드 단계명은 「청구항」, 에디터 섹션명은 「청구범위」**로 구분해 쓴다 | 청구항 | — |
| A-20 | 요약 | abstract (`InventionContext.summary`) | 발명 개요 1~2문장. ④단계에서 명칭과 함께 확정되고, 에디터 「요약」 섹션(요약서)에 대표도 표기(`【대표도】 도 N`)와 함께 조립된다 | 명칭·요약, 대표도 | **개요 금지** |
| A-21 | 부호의 설명 | reference signs (에디터 섹션) | 부호와 구성요소 명칭의 대응표 섹션. 부호 있는 구성요소로 `100: 데이터 수집부` 형식 줄을 자동 조립하며, 이후 일반 단락처럼 편집 가능. API 명세서 객체에 없는 **클라이언트 조립 섹션**(유지 결정) | 부호 | — |
| A-22 | 도면의 간단한 설명 | `drawing_descriptions` | "도 1은 …을 나타낸 도면이다" 형식으로 각 도면을 소개하는 섹션. ⑦ 확정 시 채택 도면 기준으로 자동 생성되고, 같은 분류가 연속되면 `도 1 및 도 2는 각각 …` 묶음 문장(API `idxs` 대응)으로 만든다. ⑧에서 지시 입력+다시 생성 가능 | 도면, 도 N | — |

## B. 서비스 핵심 개념 (흐름·상태)

이용 흐름을 지배하는 서비스 고유 개념. 상태값이므로 정의된 표기 외 임의 상태어를 만들지 않는다.

| # | 용어 | 대응 | 정의 | 관련 | 금지/유의 |
|---|---|---|---|---|---|
| B-01 | 작업 | task (`type:'spec'`) | 명세서 1건의 작업 단위. 「새 명세서 작성」 폼으로 생성되며 사이드바 작업 목록에 진행 배지와 함께 표시된다. 모든 상태는 작업별로 자동 저장(localStorage `axp_spec_v3_{taskId}`, 0.4초 지연) | 분석 중, 명세서 생성완료 | — |
| B-02 | 단계 | step (8단계) | 위저드의 진행 단위: ①업로드 ②발명 설명 ③이미지 선별 ④명칭·요약 ⑤구성요소 ⑥명세서 도면 ⑦청구항 ⑧중간명세서. 앞 단계의 확정 내용이 다음 단계 생성의 입력이 된다. 진행 분모는 항상 8 | 확정, 스텝바 | — |
| B-03 | 확정 | confirm | 한 단계를 마무리해 그 내용을 잠그고 다음 단계 생성을 시작하는 행위(하단 바 주 동작). 확정된 단계는 접혀 1줄 요약이 되고 내용은 읽기 전용. AI 어시스턴트 헤더에 `확정됨` 배지 | 다시 선택, 확정 내용 | 완료·저장(혼용 금지) |
| B-04 | 다시 선택 | reselect | 확정을 풀고 그 단계로 되돌아가는 행위(접힘 요약의 ✎ 버튼). 이후 단계가 확정돼 있으면 "다시 확정해야 한다"는 확인 다이얼로그를 거친다 | 확정 | 수정·재선택(표기 통일) |
| B-05 | 채택 | adopt (`adopted`/`sel`/`useForSpec`) | **결과물(명세서)에 포함시키는 것.** 발명 설명 항목·구성요소·종속항·도면(도면은 "도면 채택")에 쓰는 공통 동사이며 체크박스로 조작한다. 미채택은 흐림 처리되고 이후 단계·생성에서 제외된다 | 선택, 참고만 | 포함·반영(혼용 금지) |
| B-06 | 선택 | select (`included`) | **③ 이미지 선별 전용** — 이미지를 AI 맥락(생성 참고)에 사용하는 것. "채택"(결과물 포함)과 구분된다: 선택 이미지 중 ⑥에서 채택된 것만 명세서에 실린다. 그 외 화면의 "선택"은 배타 선택(세트 1개, 라디오)에만 쓴다 | 채택, 참고만 | — |
| B-07 | 참고만 | (⑥단계 세그먼트) | 선택 이미지를 명세서에는 싣지 않고 AI 참고용(맥락)으로만 쓰는 상태. 도 번호가 부여되지 않고 CAD 변환 대상에서 빠진다 | 채택, 선택 | — |
| B-08 | 분석 | analyze | AI가 직무발명서에서 정보를 추출·구성하는 것(업로드 분석, 구성요소 다시 분석, 단계 사이 `분석 중…`). **8단계 전체 진행 상태의 이름이기도 하다**(사이드바 배지 `분석 중`) | 정제, 생성 | — |
| B-09 | 정제 | refine (`description/refined`) | 추출된 원천 발명 설명을 AI가 다듬어 제안/종래 항목으로 재구성하는 것(② 「↻ 다시 정제」). 추출(분석)과 구분되는 후처리 개념 | 분석, 발명 설명 | — |
| B-10 | 생성 | generate | AI가 새 콘텐츠를 만드는 것(명칭 후보·독립항 세트·종속항·중간명세서·실시예·도면 설명). 재실행은 항상 「↻ 다시 생성」 + 덮어쓰기 확인 다이얼로그 | 명세서 생성 | 작성(AI 동작에는 금지 — 이용자 행위에만) |

## D. AI 상호작용

모든 AI 수정은 **① 지시 입력 → ② 제안 카드(Before/After) → ③ 적용/취소** 3단계를 따른다(즉시 반영 없음, `AI_EDIT_CONFIRM`).

| # | 용어 | 대응 | 정의 | 관련 |
|---|---|---|---|---|
| D-01 | AI 수정 | `AiEditButton`+`InlineAiEdit` (각 `*_item_modification` API) | 항목·후보·구성요소·청구항·단락 **1개**를 자연어 지시로 고치는 인라인 기능. 카드 우측 ✈ 버튼(호버 노출) → 지시 입력 → 제안 카드 | 제안 카드 |
| D-02 | 전체 AI 수정 | `AiGlobalBar` (각 `*_modification` API) | 패널의 **채택 항목 전부**에 한 번의 지시를 적용하는 상단 바(발명 설명·구성요소·종속항). 제안 0건이면 `변경이 필요 없다고 판단했습니다` | AI 수정 |
