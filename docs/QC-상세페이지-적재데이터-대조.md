## 1-3. 항목별 수정 지시

각 항목은 **[기획안] → [현재 구현] → [수정 지시] → [실제 데이터 예시]** 순서다. 예시의 URL은 `https://www.copykiller.com/patent-front/patents/{문헌번호}`.

### F-01. 문헌종류 코드가 그대로 노출 — 1,804건(100%) · 회귀

- **기획안**: 목업은 한글 명칭으로 표시한다 — `PatentDetail.tsx`의 `docKind` 파생 → `등록특허공보`
- **현재 구현**: 원본 코드 `B1`을 그대로 출력
- **수정 지시** (프런트)

```
문헌종류 = CASE document_kind
             WHEN 'B1' THEN '등록특허공보'        -- 1,801건
             WHEN 'Y1' THEN '등록실용신안공보'    -- 3건
             ELSE document_kind                   -- 미관측 코드는 원값
           END
```
- 근거: `document_kind` ↔ 문헌번호 접두 대조 불일치 **0건**(`B1`↔`10-`, `Y1`↔`20-`) → 코드로 판정해도 안전
- **주의**: 공개 문헌(`A`·`U`)은 아직 적재되지 않아 **관측된 코드가 B1·Y1뿐**이다. 추정으로 매핑을 늘리지 말고 공개 적재 후 확인한다

| 예시 문헌번호 | 현재 화면 | 수정 후 |
|---|---|---|
| `KR 10-2620137 B1` | `문헌종류  B1` | `문헌종류  등록특허공보` |
| `KR 20-0497874 Y1` | `문헌종류  Y1` | `문헌종류  등록실용신안공보` |

### F-02. 제목 영역에 국가가 두 번 — 1,804건(100%) · 회귀

- **기획안**: 국가 배지(`KR`) + 번호를 **따로** 둔다. 목업 데이터의 번호에는 국가 접두가 없었다
- **현재 구현**: 실제 `literature_number`에 국가 접두가 포함(`KR 10-…`)돼 배지와 겹친다
- **수정 지시** (프런트): 배지는 `country_code`, 번호는 **접두 제거 후** 출력

```
표시번호 = REGEXP_REPLACE(literature_number, '^[A-Z]{2}\s+', '')   -- 'KR 10-2620137 B1' → '10-2620137 B1'
국가배지 = country_code
```

| 예시 | 현재 화면 | 수정 후 |
|---|---|---|
| `KR 10-2620137 B1` | `등록공고 · KR   KR 10-2620137 B1` | `등록공고 · [KR] 10-2620137 B1` |

### F-03. 공개번호와 공고일이 한 라벨에 묶임 — 985건(54%) · 기획보완

- **왜 문제인가**(비전문가용): 「공개」와 「공고」는 **다른 사건**이다. 지금 화면은 **공개번호** 옆에 **공고일**을 붙여 놓아, 마치 그 번호가 그 날짜에 나온 것처럼 보인다
- **기획안**: 목업도 `공개/공고번호`·`공개/공고일`로 **합쳐 놓았다** → 기획안부터 분리해야 한다
- **현재 구현**: 번호는 `publication_number`(공개계 985건), 일자는 `publication_date`(공고일) — 짝이 어긋남
- **수정 지시** (기획 확정 → 프런트)

```
계열 판정:
  publication_number 가 '10-YYYY-NNNNNNN' 형식  → 공개계
        라벨 = '공개번호' / 짝 일자 = open_date       → '공개일'
  publication_number 가 'WO YYYY/NNNNNN' 형식    → 국제공개
        라벨 = '국제공개번호' / 짝 일자 = open_date   → '국제공개일'
  publication_number 가 '10-NNNNNNN' 형식        → 공고계(= 등록번호와 동일, 314건)
        라벨 = '공고번호' / 짝 일자 = publication_date → '공고일'
  publication_number 가 없음(392건)               → 번호 행 숨김 + '공고일' 단독 행(F-04)
```
- 추가 근거: `publication_date`에 **공고일이 아닌 값이 섞여 있다** — `KR 20-0497874 Y1`은 `2023-04-05`로 **등록일(2024-03-18)보다 앞서** 공개일이 들어가 있고, `KR 10-2635013 B1`은 국제공개일(`2011-11-24`)이다. 라벨을 번호 계열에서 유도해야 이런 값을 걸러낼 수 있다

| 예시 | 현재 화면 | 수정 후 |
|---|---|---|
| `KR 10-2620137 B1` | `공개/공고번호 10-2023-0126008` + `공개/공고일 2024-01-02` | `공개번호 10-2023-0126008` + `공개일 2023-08-29` / `공고일 2024-01-02` |
| `KR 10-2635013 B1` | `공개/공고번호 WO 2011/146808` + `공개/공고일 2011-11-24` | `국제공개번호 WO 2011/146808` + `국제공개일 2011-11-24` |

### F-04. 번호는 `—`인데 일자만 표시 — 392건(21%) · 기획보완

- **왜 문제인가**: 이 392건은 **공개 없이 바로 등록**된 문헌이다(조기 등록). 공개번호·공개일이 없는 게 정상인데, 화면은 `공개/공고번호 —` 옆에 일자를 띄워 **데이터가 빠진 것처럼** 보이게 한다
- **수정 지시**: 공개 관련 칸은 숨기고 `공고일`만 단독으로 표시(F-03의 마지막 분기)

| 예시 | 현재 화면 | 수정 후 |
|---|---|---|
| `KR 10-2618432 B1` | `문헌일 —` · `공개/공고번호 —` · `공개/공고일 2024-01-02` | `공고일 2024-01-02` (공개 관련 행 없음) |
| `KR 10-2619202 B1` | 동일 | 동일 |

### F-05 · F-06. 삭제된 청구항이 「독립항」으로, 서지 숫자와 목록이 어긋남 — 1,237 / 1,245건 · 기획보완 ★ 최우선

- **왜 문제인가**: 심사 중 취하된 청구항은 본문이 **「삭제」** 한 단어뿐이고 권리가 없다. 그런데 이 항들은 데이터상 인용관계(`depends_on`)가 비어 있어 화면 규칙이 **전부 「독립항」으로 분류**한다. 결과적으로
  - 「독립항」 목록에 빈 항이 섞여 **권리 범위를 오해**하게 된다
  - 서지 「청구항 수」(삭제 제외 실제 수)와 목록 개수가 **한 페이지에서 다르게** 보인다
  - 「독립항 / 전체청구항」 토글이 **같은 결과**를 내는 문헌이 309건
- **기획안**: 목업에는 삭제항이 없어 규칙이 정의돼 있지 않다 → **기획 보완이 먼저**
- **수정 지시** (기획 확정 → 프런트)

```
삭제 판정   = TRIM(claims[].text) IN ('삭제', '삭제.')       -- 4,323항 / 1,237문헌
분류        = CASE WHEN 삭제 THEN '삭제'
                   WHEN depends_on IS NULL THEN '독립항'
                   ELSE '종속항 (제' + depends_on + '항 인용)' END

독립항 모드 = 삭제 아님 AND depends_on IS NULL
전체 모드   = 삭제 아님                       -- 기본
              + 「삭제된 청구항 N개 보기」 접기로만 노출

서지 청구항 수 = claim_count                  -- 이미 '삭제 제외 수'다 (1,778건 98.6% 검증)
```
- 이렇게 하면 서지 숫자와 목록 개수가 **정의상 일치**한다

| 예시 | 현재 화면 | 수정 후 |
|---|---|---|
| `KR 10-2620415 B1` | 서지 `청구항 수 1개` / 목록 **46개 전부 「독립항」**(45개 본문이 `삭제`) · 토글 양쪽 동일 | 독립항 **1개**(제20항) · 「삭제된 청구항 45개」 접기 · 서지와 일치 |

### F-07. 값이 없는 서지 5행이 `—`로 자리 차지 — 1,804건(100%) · 기획수정

- **현황**: 「권리변동 · 최종처분상태 · 출원구분 · 실시권 등록일 · 지정국」은 **원본 채움률 0%** — 전건 비어 있다
- **기획안**: 목업이 `값 || '—'`로 **항상 렌더**하도록 되어 있다 → 기획안을 바꿔야 한다
- **수정 지시** (기획 확정 → 프런트): 0% 필드는 `—`로 채우지 말고 **행을 숨긴다.** 값이 들어오기 시작하면 자동으로 나타나게 조건부 렌더

| 예시 | 현재 화면 | 수정 후 |
|---|---|---|
| `KR 10-2620137 B1` | 5개 행이 모두 `—` | 해당 행 없음 (서지 표가 5행 짧아짐) |

### F-08. 서지 마지막 행이 반쪽 — 1,780건(98%) · 회귀

- **현재 구현**: 행은 항상 만들고, 서열목록 값이 없으면 **라벨 칸까지 사라져** 3칸만 남는다(표 정렬 깨짐)
- **수정 지시** (프런트): 기획안대로 조건부 렌더 복원. 표시할 때는 라벨 칸을 유지하고 값만 `—`

### F-09. 도면이 아직 반입 전인데 빈 패널이 보인다 — 1,717건(95%) · 기획보완

- **현황**: 도면 **이미지·도면 수는 미반입**이고, 명세서에서 파싱한 **「도면의 설명」 텍스트만** 들어와 있다
- **현재 구현**: 서지 `도면 수 0건`인데 `도면 (1)` 패널이 뜨고 `도면 이미지 없음`이 표시된다. 게다가 캡션 「도 1」 하나에 **도 1~8 설명이 뭉쳐** 있다
- **기획안**: 목업은 이미지가 있는 상태만 가정 → **미반입 상태 정의가 없다**
- **수정 지시** (기획 확정 → 프런트)

```
반입여부 = EXISTS(figures[].image)        -- 현재 0% → 전건 '미반입'

[미반입] 도면 패널 숨김(또는 '도면 준비 중' 1줄) · 서지 「도면 수」 행도 숨김
         도면의 설명은 '상세설명 > 도면의 설명' 텍스트로만 노출
[반입 후] 도면 수 = drawing_count + '건' · 패널 = figures[] 원소별 캡션 + 이미지
```

| 예시 | 현재 화면 | 수정 후 |
|---|---|---|
| `KR 10-2620084 B1` | `도면 수 0건` + `도면 (1)` + 캡션 「도 1」에 도 1~8 설명 + `도면 이미지 없음` | 도면 패널 없음 · 도면의 설명은 상세설명 안에 |
| `KR 10-2619739 B1` | 캡션 「도 1」에 도 1~3 설명 | 동일 |

### F-10. 상세설명에서 전문이 두 번 나온다 — 1,758건(97%) · 기획수정

- **기획안**: 하위섹션(기술분야·배경기술·해결하려는 과제·과제의 해결 수단·발명의 효과·도면의 설명) **다음에** 「발명의 구체적인 내용」으로 **명세서 전문(`specification`)** 을 넣도록 되어 있다
- **결과**: 하위섹션 내용이 전문 안에도 있으므로 **같은 문장을 두 번 읽게** 된다(섹션 길이 = 전문 + 하위섹션)
- **수정 지시** (기획 확정 → 프런트) — 둘 중 하나 선택

```
안 A) 「발명의 구체적인 내용」 = PARSE(specification, '발명을 실시하기 위한 구체적인 내용' 이후 구간)
안 B) 하위섹션만 기본 노출 + 「원문 전체 보기」 접기로 전문 분리
```

| 예시 | 현재 화면 | 수정 후 |
|---|---|---|
| `KR 10-2702860 B1` | 상세설명 23,022자 = 전문 20,569 + 하위섹션 2,562 | 하위섹션 + (접힘) 원문 |

### F-11. 패밀리 국가 탭이 구현되지 않았다 — 728건 · 회귀

- **기획안**: 목업에는 **국가 탭 필터**(`전체(N) · KR(n) · US(n) …`)와 국가별 건수 pill, 그리고 문헌 목록(국가·번호·출원일·명칭)이 있다
- **현재 구현**: 탭·국가별 집계 없이 번호만 **평면 나열**
- **데이터는 이미 있다**: 패밀리 문헌번호 **6,427개 전건**에 2자 국가 접두가 있다 — `US 1,426 · JP 1,153 · CN 870 · KR 794 · EP 680 · WO 446 · TW 173 …`
- **수정 지시** (프런트)

```
국가        = SUBSTRING(family.items[].literature_number, 1, 2)
국가별 건수 = COUNT(*) GROUP BY 국가        -- F-15 중복 제거 후 집계
탭          = 전체(합계) + 국가별
```
- 다만 패밀리 항목에 **명칭·출원일은 채움률 0%** 이므로 목업의 4열 목록은 **번호만** 남기고 나머지 열은 숨긴다

| 예시 | 현재 화면 | 수정 후 |
|---|---|---|
| `KR 10-2620084 B1` | 8줄 평면 나열(`TW …`, `US …`, `EP …` 순서 그대로) | `전체(7) · CN(2) · EP(1) · JP(2) · TW(1) · US(1)` 탭 + 국가별 목록 (중복 1건 제거 후) |

### F-12. 패밀리 건수를 「기계 배분」으로 만들고 있다 — 기획수정

- **기획안**: 목업 주석에 `현재 화면은 총건수 기계 배분 = ⚠파생`이라고 적혀 있다 — 국가별 건수를 **총건수를 나눠 임의 배분**한 값
- **수정 지시**: 파생 폐기. F-11의 실제 `GROUP BY` 집계로 대체. 총건수는 중복 제거 후 `COUNT(DISTINCT)`
- 예시: `KR 10-2620102 B1` — 패밀리 119건(중복 2쌍 포함) → 실제 집계로 국가별 표시

### F-13. 서지 「권리변동 —」인데 아래에 이력이 있다 — 7건 · 기획수정

- **원인**: 서지 행이 참조하는 `has_ownership_change`는 **채움률 0%**다. 반면 「권리변동 이력」 블록이 쓰는 `change_histories`에는 7건에 값이 있다

```
권리변동(서지) = CASE WHEN ARRAY_LENGTH(right_history.change_histories) > 0
                      THEN '있음' ELSE '—' END      -- 0% 필드 대신 이력 유무로 판정
권리변동 이력   = change_histories[].date + name     -- status 는 전건 null → 2열만
```
